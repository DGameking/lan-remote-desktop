## 1. 底层架构分层（描述现状，不是规划）

### 1.1 Electron 三进程 + 白名单 IPC

- **main（Node 主进程）**：设备发现、会话管理、协议适配器、存储（sql.js）、凭据（safeStorage）、日志与诊断、全部 IPC handler。唯一能访问 Node / 操作系统能力的一层。
- **preload（隔离桥）**：`contextBridge.exposeInMainWorld` 只暴露一份**显式白名单** API（`ElectronAPI`，见 `src/shared/types.ts`），逐个方法映射到固定 IPC 通道；渲染层拿不到 `ipcRenderer` 本体，也不能调用任意通道。
- **renderer（Vue 3）**：纯 UI 与状态渲染，只能通过 preload 白名单发请求；拿不到文件系统、子进程、Node 模块。
- `contextIsolation: true` + 通道常量 `IPC_CHANNELS` 单一来源（防止拼写漂移与越权调用）；统一响应包装 `IpcResponse<T> { code, message, data }`。
- 通道风格为 `domain:action`（如 `device:list`、`session:connect`、`app:getStatus`）。v1.3 新增的 `log:query`、`app:getDiagnostics`、`app:exportDiagnostics` 三个通道仍走同一白名单与同一响应包装，不新开旁路。

### 1.2 发现引擎（L1 → L2 → L3，全程只读）

- **L1 存活快扫**：{22, 445, 3389, 5900, 5666}，并发 128 / 超时 300ms。
- **L2 长尾补扫**：仅对存活 IP + ARP 种子补扫 5901-5910 / 5985 / 5986 / 548 / 8000 / 8001 / 21116，并发 64。
- **L3 只读服务指纹**：仅对开放的 `(ip, port)` 读握手层 banner / 响应 —— RFB 版本串、SSH banner、HTTP `Server` 头、SMB Negotiate 签名、RDP X.224 CR / TPKT。**只判断「是什么服务 / 大致什么系统」，不进入鉴权 / TLS / NLA / 证书层，不采集版本细节，无口令或破解逻辑。**
- **辅助手段**：mDNS（bonjour-service）与 L1 并行发起、末尾汇总；只读 `arp -a` 系统表作存活种子（无需管理员权限、不引入 Npcap，仅覆盖已通信设备）。发现主力仍是端口扫描，降级路径 = 端口扫描 + 手动添加 IP。
- **mDNS 服务类型扩展（v1.3）**：补充 `_rfb`(5900) / `_smb`(445) / `_ssh`·`_sftp-ssh`(22) / `_afpovertcp`(548)、**UDP 类型**的 `_net-assistant`(3283)，以及 `_device-info._tcp` 的 TXT(`model` / `osxvers`) 解析，增强 macOS / Linux / NAS 识别。**注意**：Windows 原生 RDP 默认不通过 mDNS 广播，`_rdp._tcp` 真实环境基本收不到，RDP 识别主力仍是 3389 端口 + X.224 Connection Confirm 握手层指纹；飞牛OS 无稳定公开的专属 mDNS 类型，靠 HTTP `Server` 头 + 5666 端口识别（详见 `docs/11` §3）。
- 每个 socket 有绝对 `setTimeout` 兜底 + settled 守卫 + `finish` 里 destroy / removeAllListeners / clearTimeout，防止句柄泄漏。

### 1.3 存储与凭据边界

- **存储**：sql.js（SQLite 编译为 WASM，纯 JS、零 native 编译）落 `userData`；打包后若 WASM 定位失败，自动降级到 JSON 文件持久化，功能不变、查询走文件。v1.2 起 `Device.detectedPorts` 通过 `ALTER TABLE ... ADD COLUMN` + JSON 默认值兼容老库，数据零丢失。
- **凭据**：Electron `safeStorage`（Windows → DPAPI）加密后 base64 落盘，`password` 永不落明文。RDP 免密另由系统 DPAPI 生成**裸 DPAPI blob 的小写 hex** 写入 `password 51:b:`；该 hex **仅同机、同 Windows 用户可解**，且与 safeStorage 的 Chromium OSCrypt v10 密文不是一回事（mstsc 不认后者，详见 `docs/09` 4.1）。
- **不进 argv / 不落明文**：生成 DPAPI hex 时明文只经 `child.stdin` 传给 PowerShell；`.rdp` 临时文件权限 0o600 且 8 秒后延时删除；密码不写入日志。

### 1.4 协议适配器「外部调起」模型

LanDesk 自研的是**发现 + 编排 + 配置 + 凭据 + 诊断**，不是远程桌面协议本身。一次连接 = 生成参数 → `spawn` 本机现成客户端 → 记录会话。

| 协议 | 调起对象 | 通道性质 |
|---|---|---|
| RDP | 系统 `mstsc.exe` + 临时 `.rdp` | 主控 ↔ 被控 `IP:3389` 直连 |
| VNC | 本机 TigerVNC / RealVNC / TightVNC Viewer | 主控 ↔ 被控 `IP:5900+` 直连 |
| RustDesk | 独立安装的官方客户端（`--connect` / `rustdesk://`） | 由官方客户端自行决定，LanDesk 不介入其链路 |
| SMB（文件通道） | Windows 资源管理器打开 `\\IP\共享名` | 主控 ↔ 被控 `IP:445` 直连 |

「进程间调用不构成衍生作品」：不复制、不静态链接、不内嵌、不重新分发任何 GPL / AGPL 组件代码。

## 2. 关于「P2P 直连」的准确结论（本轮最需要澄清的一点）

### 2.1 结论先行

RDP / VNC / SMB 从协议设计上就是 **`IP:端口` 的端到端 TCP 直连**：`mstsc`、`vncviewer`、资源管理器都是直接连到被控机的 3389 / 5900 / 445，中间**没有任何 LanDesk 或第三方中转节点**。在「同一个局域网」这个前提内，这已经是物理上最短、延迟最低的路径 —— **不存在「再加一层 P2P 才能变快」的空间**。

所谓「直连增强」，增强的**不是传输路径**，而是「发起之前」与「失败之后」。把它理解成「本轮新增了 P2P 打洞」是错误表述。

### 2.2 商业远控的「直连 / 打洞」为什么不能照搬

TeamViewer / 向日葵 / ToDesk / 网易UU远程 / 玉兔远程控制 / RustDesk 公网版那套「P2P 直连 / 会话码 / 无人值守」，依赖两样本项目明确没有的东西：

- **信令 / 中继服务**：NAT 打洞需要公网 rendezvous / 信令服务器协商，打洞失败还要 relay 中继转发；
- **被控端常驻 Agent**：无人值守、开机自启、会话码注册，都要求在被控机装一个长期运行、反过来连服务端的程序。

这两样与本项目的根基直接冲突：

| 根基 | 冲突点 |
|---|---|
| 纯局域网、无服务端、无公网 | 需要公网信令 / 中继节点 |
| 不自研协议栈、只做外部调起 | 需要自研打洞 / 穿透 / 会话层 |
| 不捆绑 AGPL / GPL、不内嵌外部协议栈 | 现成 P2P 栈多为 AGPL，内嵌即触发传染义务 |
| 零遥测、不采集设备信息 | 会话码 / 设备 ID 注册本质是向服务端登记设备 |
| 被控端用现成开源服务、不新装常驻程序 | 要求被控端常驻自启 Agent |

因此：**公网打洞 / 中继 / 信令 / 会话码 / 无人值守是「明确不做」，不是「能力缺口」**，不列入待办、不写进路线图。任何以「补齐 P2P」为名引入上述组件的方案，都会改变产品定位，须重新立项，而不是在本版本内追加。四款商业产品的逐项对照与「能借 / 借不来」的判断见 `docs/11`。

### 2.3 本轮 v1.3 实际优化的是什么

一句话：**让既有直连「更顺、更可诊断、更安全」**，不碰传输路径本身。

- **更顺**：端口预检轻量重试（2 次，取最小延迟）；RustDesk 引入 `skipped` 语义（预检跳过，不再被误显示为「端口不可达」）；快速连接失败时按协议给出分类排查指引 + 端口预检按钮；全局合规声明确认后连接对话框默认勾选（仍可取消），减少重复勾选；RDP 免密限制明示；WoL 远程唤醒与 mDNS 服务类型扩展让「找到并叫醒设备」更顺。
- **更可诊断**：结构化 JSON Lines 日志 + `traceId` 贯穿一次连接 + 运行状态快照 + 一键导出诊断包（见 `docs/12`）。
- **更安全**：内网管理页入口严格防 SSRF；DPAPI hex 大小写归一化；改用户名但密码留空时不再误用旧账号密码；日志按字段清单脱敏。

## 3. 能力现状矩阵（已有 / 本轮增强 / 明确不做 / 后续演进）

> 「后续演进」仅为候选方向，不代表排期或交付承诺。本轮已交付范围以 `RELEASE_NOTES.md` 的 v1.3.0 段为准。

| 能力 | 归类 | 现状与取舍理由 |
|---|---|---|
| 分层扫描 + 只读服务指纹 | 已有（v1.2） | 只到握手层识别，不进鉴权；够用于「连哪个端口 / 什么协议」，不做深度探测 |
| 通用 `IP:端口` 快速连接 | 已有（v1.2） | 不依赖扫描，是多网卡 / AP 隔离下的必备兜底 |
| 账密托管 + RDP 免密直连 | 已有（v1.2） | 基于系统 DPAPI；本轮只修遗留缺陷，不扩展免密作用域 |
| 共享剪贴板 / 文件传输 | 已有（v1.1） | 全量复用 RDP / 客户端 / SMB 原生能力，LanDesk 不自研传输协议、不缓存内容；**Explorer 的 SMB 复制不支持可靠断点续传，现有「传文件」通道不承诺断点续传** |
| 结构化日志 / traceId / 运行状态快照 / 诊断包导出 | **本轮增强** | 零遥测前提下，把状态变成可查、可导出、可交给 AI 分析的本地结构化数据 |
| 端口预检重试 + RustDesk `skipped` + 分类排查指引 | **本轮增强** | 解决「连不上却不知道为什么」，降低误判 |
| 内网管理页入口（Web 管理端口） | **本轮增强** | 复用已发现的开放端口，仅内网 IP + 端口白名单校验，防 SSRF |
| **WoL 远程唤醒** | **本轮增强** | 对已发现 MAC 发 UDP Magic Packet（**102 字节 = 6×0xFF + MAC×16**），零新增依赖、零服务端；best-effort、**无送达回执**，需被控端 BIOS/网卡预开且接有线，**仅同网段有效**、跨网段/无线通常不生效，**不宣称「设备已开机」**；不引入被控端常驻 Agent |
| **mDNS 服务类型扩展** | **本轮增强** | 补含 UDP 类型（`_net-assistant`）的服务发现与 `_device-info._tcp` TXT(`model`/`osxvers`) 解析，增强 macOS/Linux/NAS 识别；本地解析、不依赖云端，不编造飞牛OS 专属类型；RDP 仍以 3389 + X.224 握手层指纹为主 |
| DPAPI hex 归一化 / 改用户名不误用旧密码 | **本轮增强（修复）** | 修独立 QA 集成审查遗留问题，避免免密静默降级 / 串号 |
| 合规确认默认勾选 / RDP 免密限制明示 | **本轮增强（体验）** | 减少重复操作，同时把系统策略边界讲清，不绕过策略 |
| 公网打洞 / 中继 / 信令 / 会话码 / 无人值守 Agent / 账号体系 / 2FA / 防暴力破解 / 自研 E2EE / 自研文件传输协议 / 常驻剪贴板同步 / 会话时长·码率·帧率统计 / 内建 SSH 或 VeNCrypt 隧道 | **明确不做** | 见 §5 完整清单；均需服务端/Agent/账号体系，或属被调起通道自身协议栈 |
| 内嵌 AGPL(GPL) 协议栈 / 自研 VNC 画面渲染 | **明确不做** | 许可传染 + 超出「外部调起」模型，属重新立项范畴 |
| 云端遥测与诊断上报 / 崩溃自动上报 / 任何遥测外发 | **明确不做** | 零遥测承诺；设置中保留一个默认关闭的预留开关（`telemetryConsent`），**当前版本无论其取值都不产生任何采集或上报行为**，仅为未来版本预留 |
| 移动 / iOS / 鸿蒙 / Web 主控、账号云同步、会话录像 | **明确不做**（沿用） | 沿用既有边界，见 README 第二节 |
| 轻量在线心跳 / 收藏·置顶·别名·最近连接一键重连 / SMB `robocopy /Z` 断点续传 / SSH 终端入口 / WS-Discovery·NetBIOS 补 Windows 主机名 | 后续演进 | 逐项理由见 `docs/11` §6；本轮聚焦连接可用性与可观测性，避免范围膨胀 |
| 诊断导出支持 `dialog.showSaveDialog` 自选路径与导出前勾选包含项 / 状态快照补 `capabilityMatrix` 静态副本 | 后续演进 | 逐项理由见 `docs/12` §10；本轮先保证「固定路径 + 自包含 + 安全默认」 |
| 代码签名、RustDesk 深度集成、跨网段发现增强 | 后续演进 | 需证书 / 外部依赖 / 更多网段策略，非本轮范围，单独立项评估 |

## 4. 「AI 后续如何获取状态」的准确边界

**先把不能做的说清楚**：LanDesk 没有服务端、没有对外的监听 API、零遥测、不注册任何设备 ID。因此**任何 AI / 助手 / 云端都无法远程连进本机进程**去「实时读取状态」或「远程调试」—— 软件在设计上就没有这条通道，v1.3 也没有新增。把它写成「AI 可远程连接软件」是错误表述。

**能做的是「本地结构化产出 + 用户主动转交」**：

1. 软件在本机 `userData/logs/*.jsonl` 写结构化日志，并在 `userData/diagnostics/`（固定路径）由用户一键导出**自包含诊断文本**（含版本 / 平台 / 运行时长 / 存储模式 / 协议可用性 / 各类计数 / 最近会话 / 最近错误 / 按 `traceId` 串起的连接链路，且按字段清单脱敏、不含任何凭据）。
2. 用户有三种方式把状态交给 AI：在设置页「运行状态与诊断」面板查看并点「一键复制」→ 粘贴给 AI；或导出诊断包后把文件交给能读本地文件的 AI；或直接把 `userData/logs/*.jsonl` 的相关片段贴给 AI。
3. AI 据此**阅读、定位、给出优化建议或改法**；是否采纳、如何修改由用户 / 开发者决定。**AI 不写入、不控制、不反向连接本软件。**

这条边界与「零遥测」一致：主进程只写本机固定路径，**不存在任何自动外发通道**；数据出不出本机，完全由用户一次主动复制 / 导出动作决定。落地字段与操作步骤见 `docs/12`。

## 5. 明确排除项与理由（完整清单，避免被当成遗漏）

| 排除项 | 理由 |
|---|---|
| 会话码 / 设备 ID 注册 | 本质是向服务端登记设备，需账号体系与信令；与「不采集、不上传设备信息」冲突 |
| P2P 打洞 / NAT 穿透 | 需公网 rendezvous / 信令；局域网内本就是 `IP:端口` 直连，无收益 |
| 中继服务器 / relay 转发 | 引入中转即破坏「端到端直连、无中转」定位，并产生服务端运维与隐私责任 |
| 信令服务 / rendezvous | 同上，且要求被控端与服务端保活注册 |
| 无人值守 / 被控端常驻自启 Agent | 要求被控机新装常驻程序，超出「被控端用现成服务、不新装程序」边界 |
| 账号体系 / 登录 / 设备云同步 | 需中心服务与用户数据托管，与「无账号、无服务端」冲突 |
| 2FA / 二次验证 | 依赖账号体系与服务端校验，本地单体无从承载 |
| 防暴力破解（服务端限流 / 封禁） | 属服务端或被控端策略；LanDesk 不接管认证，不宣称提供 |
| 端到端加密（自研 / 宣称） | **由被调起的通道提供**（RDP TLS、RustDesk 官方客户端自带 E2EE）；LanDesk 不提供、不控制协商，也**不宣称提供**（见 §6） |
| 自研文件传输协议 | 全量复用 RDP 重定向 / SMB / 客户端原生能力，不自研、不经手内容 |
| 常驻剪贴板同步（断开会话后仍同步） | 需中心服务，与「无服务端」定位冲突 |
| 会话时长 / 码率 / 帧率统计 | 画面与媒体流由外部客户端承载，LanDesk 不接触，无从采集也不采集 |
| 内建 SSH / VeNCrypt 隧道 | 属 Viewer 与服务端协商的协议栈能力，LanDesk 只 `spawn` 调起、不控制协商；不内嵌 GPL/AGPL 栈 |
| 内嵌 AGPL / GPL 协议栈 | 触发开源传染义务；本项目仅进程调起独立客户端，不内嵌、不捆绑、不修改 |
| 云端遥测与诊断上报 / 崩溃自动上报 / 任何遥测外发 | 零遥测承诺；崩溃信息只在本地日志中按需查阅，诊断数据仅本地产出、是否分享由用户主动决定；设置中默认关闭的预留开关（`telemetryConsent`）当前不产生任何采集或上报行为 |
| VNC 画面自研渲染 | 需自研 RFB 协议栈与画面管线，超出「外部调起」模型且许可 / 工作量风险高 |

## 6. 安全边界（本轮未放宽，逐条沿用并强化）

- **VNC / 基础 RFB 是明文协议**：RFB 安全类型只有 `None` / `VncAuth`，**VncAuth 仅保护最多 8 字符密码**，而**帧缓冲、键鼠、剪贴板全部明文**；加密需 VeNCrypt / SSH 隧道，且**取决于 Viewer 与服务端协商结果**，LanDesk 只 `spawn` 调起、**不控制也不参与该协商**。因此**绝不宣称「VNC 已加密」**，只做「仅可信局域网」警示 + 引导改道 RDP / RustDesk / SMB。标准 VNC 不含文件传输。
- **RDP 保持 TLS + CredSSP / NLA 默认不降级**：不为免密关闭安全协商，避免中间人风险；Credential Guard / 空密码账户自动回退手输，**不绕过系统策略**。
- **端到端加密归属**：由被调起的通道提供（RustDesk 官方客户端自带 E2EE、RDP TLS），LanDesk **不提供也不宣称提供**端到端加密。
- **密码绝不进 argv**：明文只经 `child.stdin` 传给系统组件，不进入进程命令行、不写明文 `.rdp`、不进日志。
- **`.rdp` 临时文件 0o600 且 8 秒删除**：最小权限 + 最短存活窗口。
- **DPAPI 密文仅同机同用户可解**：换机 / 换 Windows 用户即失效，这是设计而非缺陷。
- **日志按字段清单脱敏**：密码类字段、账号名、含用户名的本机路径、共享名会被脱敏；**局域网私有 IP 在日志中保留完整**（按 IP 串联一次连接是诊断定位必需），但**状态快照与诊断文本里的网段、本机路径做掩码 / 去用户名处理**；日志仅本机保存、不自动上传（字段清单见 `docs/12` §3）。诊断快照与诊断包**不含任何凭据、明文密码、DPAPI hex**。
- **管理页入口防 SSRF**：仅对**内网 IP**、且端口必须在该设备 `detectedPorts` 白名单内才允许用系统默认浏览器打开 `http://IP:端口`；**不开放任意 URL 输入**，不接受域名、公网地址、协议串或白名单外端口。
