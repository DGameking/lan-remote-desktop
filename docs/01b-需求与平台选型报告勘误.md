# 需求与平台选型报告勘误页（01b）

> 关联主文档：`docs/01-需求与平台选型报告.md`
> 依据：团长 Phase 1 裁决——**采纳选项1（外部调起 mstsc/VNC Viewer，主控端不渲染画面、不录流）**，选项2（内嵌自研渲染）与选项3（混合）均否决。
> 性质：本页仅修订主报告第四章 4.2 成本估算口径及联动条目；端形态、需求池、KANO 分类、平台选型结论均不变。

## 一、裁决确认要点（勘误前提）

1. **编号勘误**：REQ-009 = 连接历史与一键重连；REQ-010 = 会话基础操作（键鼠/全屏切换/断开）。已澄清 product-manager 的"REQ-09 笔误"。P0 严格为 **REQ-001~012 连续 12 项**（REQ-012 手动加 IP 源自期望型，提为 P0）。
2. **性质判定**：研发"外部调起、不渲染"与 REQ-010 **不是需求冲突，而是实现主体归属差异**。REQ-003~006 + REQ-010 保留在需求池，实现主体标注为**外部客户端**；本产品验收 = 发现设备 → 按平台选协议 → 注入/调取凭据 → 拉起外部客户端建会话 → 断开后回收，**不含画面渲染、键鼠映射、剪贴板、缩放**。
3. **端形态不变**：Windows 桌面软件唯一主控端（Electron + TypeScript）+ 被控端各平台现成开源服务/Agent；不做 Web/App/小程序。

## 二、勘误正文：第四章 4.2 成本可行性

### 2.1 修订前（主报告原文，作废）

> 开发成本：12 个 P0 功能点，按桌面工具 2~4 人日/点 + 协议联调 buffer → **约 40~80 人日**。≤20 人日则降配为"RDP+VNC+最简发现+手动加 IP"。

### 2.2 修订后（以本页为准）

**开发成本：约 20~40 人日**（原 40~80 人日作废）。

缩减原因——**实现主体转移**：裁决采纳外部调起后，画面渲染、键鼠映射、剪贴板同步、分辨率缩放适配这四层由外部成熟客户端（Windows 远程桌面 mstsc / VNC Viewer，可选 RustDesk）承担，我方不再自研协议栈渲染层与输入映射层。主控程序职责收敛为"**发现 + 编排 + 配置 + 凭据 + 生命周期回收**"，剩余工作量全部落在本方可控的轻量模块上。

修订后工作量拆分（区间估算，非报价）：

| 模块 | 人日区间 | 说明 |
|------|----------|------|
| 主控 GUI 骨架（设备列表/详情/设置/历史） | 6~10 | Electron+TS，单窗口工具类 UI |
| 设备发现模块（mDNS/SSDP/ARP/端口扫描） | 4~8 | 多网卡与 AP 隔离场景适配为主要变数 |
| 协议编排与外部客户端调起 | 4~8 | 参数化拉起 mstsc/VNC Viewer、会话回收、失败回退 |
| 凭据管理 + 连接历史 | 3~5 | DPAPI/OS keyring 加密、历史 50 条 |
| 被控端开启指引 + 端口连通性自检 | 1~2 | 纯文案与 socket 探测 |
| 打包分发 + GitHub 仓库/Releases/README | 2~4 | 自分发、无商店流程 |
| 联调与测试 buffer | 2~3 | 四类被控端实机验证 |
| **合计** | **20~40** | 较原估算下降约 50% |

### 2.3 联动修订

- **4.1 技术可行性**：仍为"可行，中低风险"，但攻关点减少——原"VNC 方言（Tight/Ultra/Zlib）与认证方式兼容"转由外部 VNC 客户端承担；我方仅余"多网卡/虚拟网卡/AP 隔离下的发现稳定性"与"外部客户端参数化调起兼容性"两项。
- **4.3 时间可行性**：由"约 8~14 周（可裁剪版约 6 周）"下修为 **约 4~10 周**（按每周 4~5 人日有效投入）；可裁剪版（RDP+VNC+最简发现+手动加 IP）约 **3~5 周**。仍无商店审核/ICP 备案瓶颈。
- **4.4 合规可行性**：仍为中风险，但**许可证传染风险进一步降低**——主控端不含任何 GPL/AGPL 协议栈源码、不静态链接相关组件，仅以外部进程方式调起独立客户端，不构成衍生作品；主控端采用 MIT/Apache-2.0 的方案不受影响。外部客户端自身许可证由其各自承担。
- **风险汇总**：技术 中低 / **成本 中低（原"中"，因工作量减半且预算仍待确认）** / 时间 低 / 合规 中。
- **第五章待确认第 1、2 项**：预算假设同步改为"零到低现金、**20~40 人日（约 4~10 周兼职）**"；若收紧至 ≤15 人日，降配方案为"RDP+VNC+最简发现+手动加 IP"，砍掉完善发现与指引自检。
- **第一章预算/时间假设行、第六章"预算/时间收紧仅触发功能裁剪"结论**：人日数值同步以 20~40 为准，其余表述不变。

## 三、勘误新增的合规提示（外部调起特有）

1. **凭据注入不得走明文命令行参数**：Windows 命令行对其他进程可见，禁止以 `mstsc /password:xxx` 等形式传递密码。应通过临时 `.rdp` 凭据文件、VNC 密码文件或标准输入传递，会话建立后立即删除临时文件。
2. **外部客户端版本与来源需在 README 声明**：仅调起用户本机已安装或官方渠道下载的客户端，不在仓库内捆绑第三方二进制，避免把外部许可证义务转移给本仓库。
3. **用途红线不变**：首次运行仍需声明"仅连接你有权访问的设备"；禁止内置打洞、弱口令爆破、绕过认证能力；凭据本地加密、不上传。
