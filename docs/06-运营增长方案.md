# LanDesk 运营增长方案（Phase 5 · Rev1.4 终裁定稿）

> 编写：growth-operator｜依据：growth-retention.md｜场景转译：开源免费 + 无账号 + 无云端 + 无服务端 + 外部调起模型 + GitHub Releases 自分发
> AARRR 转译：Acquisition=社区内容带来下载；Activation=下载→首次成功拉起外部客户端并确认会话存活(Aha)；Retention=WSCS；Revenue→社区价值产出(Star/Fork/Issue/贡献者)；Referral=Star/Fork/awesome/教程传播。

> **首版数据三源（铁律）**：① GitHub Insights/Releases API（下载/Star/Fork/Clone 硬数据）；② 用户自愿反馈（脱敏本地日志 + Issues/Discussions）；③ 48h/1 周人工回访。**首版 v1.0.0 零遥测**：无上报模块、无 opt-in 开关、无端点，外发请求数=0。凡标注「V2 遥测上线后启用，首版不生效」的字段，首版一律不采集、不计算、不作为放行或复盘指标。

## 1. 指标基线

北极星 **WSCS（周成功远程连接会话数）**：7 天内计入的会话总数。外部调起模型下主控端不渲染画面，故"成功"口径 = 成功拉起外部客户端 **且** 满足任一存活信号：① 托盘「结束会话」本地信号（精确、优先）；② 外部进程从拉起到退出存活≥30s（近似，单实例复用会失真）。二者取其一不重复计数。作为**趋势指标**，不作单会话精确计费。基线 0；目标第 4 周≥50/周、第 12 周≥300/周。
**首版测量**：托盘本地信号 + 用户自愿反馈近似（不上报）；V2 遥测上线后启用精确上报，首版不生效。

| 指标 | 口径定义 | 当前基线 | 目标值 | 测量方式（首版 / V2） |
|---|---|---|---|---|
| 下载量 | Releases asset 累计下载 | 0 | 第4周≥400 / 第12周≥2000 | GitHub Releases API（硬数据·首版生效） |
| Star 数 | 仓库 Star 累计 | 0 | 第12周≥300 | GitHub Insights（硬数据·首版生效） |

| 端到端感知时延 | 点击→用户看到可用画面（含外部客户端与网络） | 内测≈10s | P95≤8s（运营观测·非放行） | **V2 遥测/用户反馈，首版不精确**；超标先归因（见下） |
| 外部客户端调起成功率 | 成功拉起进程 ÷ 请求 | 待采集 | ≥99% | QA `PERF-02`（首版可测·门禁） |
| 崩溃率 | 崩溃会话 ÷ 总启动会话 | 无 | **≤0.1% 质量目标值 / V2 遥测上线后可度量，首版非放行门禁**；不设 <0.5% 告警线 | `app_crash`/`app_launch` **V2 遥测，首版不生效**；首版放行依据=QA 6.1§9 定性 P0=0 + Issues 1h≥3 例绝对数 |
| 首启成功率 | 首次启动无崩溃且进主界面 ÷ 首次启动数 | 无 | ≥95%（目标值） | 来源 `app_launch`，**V2 遥测，首版不生效**；首版以定性 P0=0 替代 |
| Issue 首响时长 | 维护者首次回复 Issue 时间中位数 | N/A | ≤48h | GitHub Issues（首版生效·运营 SLA） |
| opt-in 同意率 | ~~同意遥测用户 ÷ 展示选项用户≥25%~~ | — | **删除**（首版零遥测无 opt-in 开关） | V2 演进如启用遥测再设，首版不存在 |

**双时延归因规则**：调起段≤3s 但端到端>8s → 外部客户端/被控端网络问题，非本产品缺陷，运营记录反馈、不触发 P0；调起段>3s → 研发/测试 P0，优先修复。不混用。

**首版数据纪律**：样本口径严禁当全量汇报；首版所有定性结论须可追溯到三源之一；V2 遥测字段在表中已统一标注，首版一律不纳入复盘与放行。

## 2. 冷启动（3 个主攻渠道）

种子画像：飞牛OS/群晖 NAS + 混合 OS 玩家；2-5 台设备小工作室/家庭管理员；关注 RustDesk 因 AGPL 找替代的自托管爱好者。
- **A 飞牛OS/NAS 社区**（最精准）：每周 1 帖实测教程 + 专属反馈入口 + 一对一邀请前 50 用户。首月 100-200 下载。
- **B V2EX + 少数派**：V2EX 分享创造每周 1 帖、少数派每月 1 篇深度图文。首月 200-400 下载。
- **C GitHub 生态**：提交 awesome-selfhosted/awesome-remote-desktop、竞品讨论区合规参与（不灌水挖坟）。首月 100-300 下载。
- 前 100-1000 用户进 Discussions"创始用户"区，给 README 致谢墙/Contributors/Release 点名/优先体验的身份感。README/Release Notes=转化页（一句话价值、30 秒 GIF、平台矩阵、与 RustDesk/TeamViewer 客观对比、5 分钟快速开始、双许可声明）。首月不全渠道铺开。
- **给运维/团长的量级提示**：三渠道首月下载 400-900、第 12 周累计≥2000；分发托管 GitHub Releases，无自建服务端，容量带宽压力可忽略、无需专项扩容。

## 4. 留存激活（重点）

"用户为什么来第二次"：① 常用设备/连接历史沉淀（REQ-009：会话回收 100% 记录、一键重连≥95%）使复发成本≈0；② 设备变化重新发现；③ 版本迭代新平台协议。
- **新手≤3 步到 Aha**：启动→合规/隐私声明 + 首启确认（未确认阻止连接，QA `TC-COMP-E01`；首版无 opt-in 开关）→"开始扫描"；自动扫描（端口扫描 3389/5900 为主力 + mDNS 取设备名线索 + 只读 ARP 补充，三者默认启用）→"发现 N 台"列表并标注平台（来源 inferred/manual；自动识别仅弱提示，首次连接请用户确认平台并记住，用户侧体验仍是"按平台自动推荐"）；点击→外部调起→首次成功拉起且会话存活即 Aha（此刻才引导 Star/讨论区）。
- **被控端部署指引 = 首次成功关键杠杆（REQ-011，P0）**：连接失败内嵌分平台图文指引（Win 开远程桌面 / mac 开屏幕共享含屏幕录制权限 / Linux 开 VNC·SSH 仅辅助配置 / fnOS 开远控）；自检 ping+端口探测给三类结论（离线/端口未开/防火墙拦截，≥90%）。扫描 0 台给 3 步排查清单（同网段?已开远控?防火墙放行 3389/5900?）+ 一键重扫 + 手动添加 IP（REQ-012）。这是激活率≥60%/70% 与实验 1 的载体。
- 习惯养成（工具型不搞签到）：挂既有习惯（回家连主机/出门连 NAS/开机连工作站）、常用置顶+历史、在线状态"它还在"、每月稳定版本 + Release Notes。
- 触达红线：Star 引导每用户≤2 次仅愉悦时刻单会话≤1 次、22:00-8:00 不弹、"不再提示"永久生效；版本提示每版≤1 次；Release 通知大版本/安全修复≤2 次/月；社区帖每周≤2。绝不弹窗轰炸索取 Star。会员积分不适用 → 社区贡献激励（Contributors/致谢墙/Release 点名/创始用户身份）。

## 5. 流失召回

流失定义：14 天无计入 WSCS 的成功会话。新用户流失（7 天未首连）→降门槛指引 + 排查清单；活跃衰退（连续 2 周降）→找原因 + Release 通知；沉睡（>14 天）→新版本卖点。无账号 → 无 Push/短信/邮箱，召回能力天然弱，优先级 Watch/Release → 社区帖 → 应用内，资源前移到激活留存。
- **首版召回受限**：无账号无遥测 → 无法主动识别流失用户、无法定向触达；首版仅能通过社区帖/Release 泛触达 + 自愿反馈者人工维系。分层召回的精准执行依赖 V2 遥测上线后启用，首版不生效。
- 质量衡量："召回后 7 日二次流失率"同样依赖 V2 cohort，首版不计算；首版以人工回访定性观察。

## 6. 看板与周报

- **首版看板（仅三源）**：获客=Releases 下载量/Star/Fork/Clone/渠道来源（GitHub Insights 硬数据 + UTM）；质量=崩溃/首启等**首版不可量化**，改看 QA 门禁结果（P0 数、核心链路通过率、PERF-02/03/05、首版零外发 SEC-10）+ Issues 绝对数与首响；反馈=Issue 数/分类/首响、讨论区、贡献者；WSCS=托盘本地信号 + 自愿反馈近似（趋势、非精确）。
- **V2 看板（遥测上线后启用，首版不生效）**：激活漏斗（download→`app_launch`→`connect_success`）、cohort 次日/7日留存、端到端时延、WSCS 精确值、同意率。
- 周报模板：北极星 WSCS 趋势；AARRR 五项（首版注明哪些为 V2 不生效）；留存曲线是否走平（V2）；质量红色项（首版=QA 门禁+Issues，V2=遥测）；本周实验结论；下周 Top3。漏斗诊断口诀：下载→启动低=安装包/兼容；启动→首连低=引导/被控端指引；首连→留存低=核心价值。先修漏斗再拉新。

## 7. 实验计划

- 实验 1（首选）：连接失败页内嵌分平台被控端指引使激活率 60%→70%（载体=REQ-011 P0）。**首版样本口径**：因零遥测，实验 1 的激活率量化 A/B 依赖 V2 遥测，首版不生效；首版以自愿反馈 + 人工回访做定性验证，V2 上线后跑严格 A/B（样本≥100 opt-in，2 周，显著提升全量/无差异记录/下降回滚）。
- 实验 2：README 30 秒 GIF vs 静态截图对 Visit→Star/Fork 的影响——此实验可用 GitHub Insights 硬数据 + UTM 在首版执行。
- 所有实验含失败入台账，沉淀认知资产。

## 9. 反馈闭环

Issue 模板三类（Bug 报告/被控端兼容/功能建议，含主控端与被控端 OS、网络拓扑、脱敏日志）；Discussions 四类（Ideas/Q&A/Show-and-tell/Announcements）+ 置顶"连不上排查指南""被控端开启教程合集"；CONTRIBUTING.md/good first issue/PR 模板/DCO/致谢，高频反馈者转贡献者。首版反馈闭环是三源中"用户自愿反馈"的核心载体，权重高于 V2 遥测。

## 11. v2 优先级框架

P0（阻断）首周崩溃/连接 Top 问题 + 纠正后协议推荐正确率不足 100% 时修复记忆链路（自动识别优化降为 P2）；P1（激活杠杆）漏斗最差环节（多为被控端指引/发现命中率）；P2（高频诉求）平台/协议支持 + 自动识别覆盖率优化；P3（体验资产）README/教程/社区。同分级内按"影响面×置信度÷成本"排序，跨级 P0/P1 不可被挤占。**V2 遥测立项评估**（若需精确漏斗/留存/时延）纳入 90 天复盘决策，首版不预设。

## 12. 风险

无商业化预算 → 社区内容 + 时间成本，做长期复利资产；冷启动慢 → 一对一定邀 + 身份感；召回难 → 重心前移激活留存；**首版零遥测 → 无精确漏斗/留存数据，靠三源定性 + QA 门禁 + 人工回访，禁止杜撰量化值**；无服务端易错配 → README 明确"不支持公网远控"减无效 Issue。分发托管 GitHub Releases 容量带宽压力可忽略。

## 13. 团长裁决附录（与正文冲突处以此为准 · Rev1.4 终裁更新）

1. **首版零遥测（铁律，已源码实证）**：v1.0.0 无上报模块、无 opt-in 开关、无端点，唯一 telemetryConsent 预留位默认 false 且无 UI，README 隐私 v1.5 定稿"不包含崩溃自动上报功能"，外发请求数=0。正文中所有依赖 opt-in 遥测的字段（WSCS 精确值、cohort 次日/7日留存、漏斗各阶段转化率、同意率≥25%、100 样本门槛、端到端时延遥测、崩溃率/首启实际值）在首版**一律标注「V2 遥测上线后启用，首版不生效」**，不采集、不计算、不作为放行或复盘指标。首版数据仅三源：GitHub Insights/Releases API、用户自愿反馈、48h/1 周人工回访。
2. **发现命中率分母**：分母 = 已开启 RDP/VNC 服务且网络可达的设备（端口扫描接近 100% 可达标）；未开服务的手机/IoT 不计入分母。**不要求 nmap/arp-scan 交叉验证作为放行前提**——代码侧发现主力为端口扫描 + mDNS，ARP 为只读补充（PERF-05）。
3. **WSCS 精确信号**：由托盘「结束会话」入口 + 外部进程存活≥30s 近似信号共同构成（已纳入代码实现），但首版不上报，仅作本地信号 + 用户自愿提供的本地日志中可见，用于趋势观察。
4. **平台识别准确率 ≥95% 作废（Rev1.4 更新）**：协议层（VNC banner）不携带 OS 字段，自动识别仅作弱提示、不设准确率硬指标、不作 P0 放行门槛。放行 = 平台可手动指定/纠正并持久化 + **纠正后协议推荐正确率 100%**；手动纠正率保留为运营观测项。（原"≥95% 目标值"表述作废，与 02c 第三章定稿一致。）
5. **崩溃率口径（Rev1.4 更新）**：≤0.1% 为质量目标值 / V2 遥测上线后可度量，**首版非放行门禁**（首版零遥测无法计算实际值，设为门禁会导致发布卡死）；**<0.5% 看板告警线已删除**（无数据源的告警线无意义）。首版稳定性放行依据 = 定性 P0（启动崩溃/数据丢失）=0 + GitHub Issues 1h≥3 例绝对数未触发（QA 6.1§9）。
6. **其余正文**（冷启动三渠道、README ASO 关键词、≤3 步 Aha 引导、被控端指引杠杆、触达红线、90 天节奏、v2 优先级框架、双时延区分）全部生效。
