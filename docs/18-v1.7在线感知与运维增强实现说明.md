## 二、核心工程项：写放大治理

sql.js 每次 `persist()` 都会把整个数据库序列化写盘。若按"每台设备每轮探测写一次"实现，100 台设备 × 每分钟一轮 = 每分钟 100 次全库写盘，性能必然塌陷。

解决方案是新增 `Store.setDeviceOnlineBatch(updates)`：

- 一次性查出当前 `ip → online`，与期望状态做差；
- **只更新真正翻转的行**，无翻转直接返回 0，不调用 `persist()`；
- 有翻转时整批共用**一次** `persist()`；
- JSON 降级实现同款语义，保证两种存储行为一致。

`OnlineMonitor` 每轮动态读取设备列表作为探测目标（避免缓存陈旧），并发分批上限 8，窗口失焦时每 3 拍探 1 次。落盘失败时**抑制状态推送**，避免 UI 显示与持久化状态短期矛盾（用户看到"状态自己跳回去"）。

## 三、跨模块集成修复（本次发现并修掉）

这一轮按 v1.6 的教训"typecheck 过不等于功能通"，逐条读码核对了「UI 设置 → IPC 校验 → 存储持久化 → 主进程调度真正读取」，发现并修复：

1. **布尔设置键还原遗漏**：`store/index.ts` 的布尔键集合缺 `onlineRefreshEnabled`，KV 底层只存字符串，读回 `'false'` 时 `el-switch` 会把非空字符串判为真，导致"开关显示开、巡检实际关"。已把还原规则改为按 `DEFAULT_SETTINGS` 类型分组，并加元测试自动拦截未来新增字段的遗漏。
2. **数值设置键未还原**：`rdpWidth`/`rdpHeight`/`onlineRefreshIntervalSec`/`autoScanIntervalMin` 读回是字符串，`el-input-number` 收到 `'60'` 会错位。新增数值键还原，脏数据回落到默认值。
3. **调度器未随退出释放**：`registerIpc` 新增的 `IpcSchedulerHandle` 未被 `main/index.ts` 使用，`before-quit` 没停定时器。已接收句柄并在退出时 `disposeSchedulers()`。
4. **设置变更未即时生效链路**：已核对 `settings:set` 与数据导入两条路径都调用 `applySchedulers()`，开关无需重启。

## 四、安全核对

- 延迟测速 / 在线探测的 IP 经 `isValidIp()` 严格 IPv4 校验，端口 1..65535；
- 在线目标只来自本机库内已发现设备，不接受 renderer 任意 IP；
- 协议链接只做参数预填，必须用户手动确认才发起连接；解析层严格 IPv4（无前导零）、单冒号（拒绝 IPv6 与认证写法）、协议白名单、`landesk:` scheme 限定；
- 全程不拼 shell 命令，不引入任意 URL 打开；
- `landesk://` 协议关联只在打包版、当前用户级（`HKCU\Software\Classes`）注册，不需管理员权限、不联网；开发模式跳过（否则会指向 electron.exe）。注册失败只记日志，不影响启动，命令行参数路径始终可用。
