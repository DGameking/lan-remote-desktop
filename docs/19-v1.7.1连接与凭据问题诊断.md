# v1.7.1 连接与凭据问题诊断（本机实测，2026-11-24）

## 一、现象与结论速览

用户反馈两问：① 为什么无法进入远程桌面？② 为什么记不住账号密码、每次都要重新注入？

本机实测环境：
- 安装版本 LanDesk 1.7.0，数据目录 `%APPDATA%\LanDesk`
- 目标 `192.168.10.15`，RFB 横幅 `003.889` → 识别为 macOS 屏幕共享
- 本机 Viewer：TigerVNC v1.16.2（`C:\Program Files\TigerVNC\vncviewer.exe`）、RealVNC Viewer 均在
- 日志：`logs/lanDesk-2026-11-24.jsonl`；数据库：`landesk.sqlite`

三条铁证：

| 证据 | 来源 | 含义 |
|---|---|---|
| 端口 5900 可达、延迟 11–77ms | `precheck.done` | 网络与端口没问题 |
| Viewer 被成功调起 | `已调起 VNC Viewer` | 调起动作本身成功 |
| 16 秒后 `session.ended reason=process-exit` | 会话日志 | 会话被本机判定"外部进程退出"而回收 |
| `credential.resolved reused:false` ×3 | 会话日志 | 已存凭据从未被复用 |
| credentials 表确有 vnc/mac/48 字节密文 | SQLite 直读 | 凭据保存成功，问题在"用"不在"存" |

## 二、问题一：无法进入远程桌面 —— 三个叠加原因

1. **会话被误判退出（本软件 bug，已修）**
   `SessionManager` 用"启动 PID 是否存活"判断会话是否结束：宽限 10 秒 + 每 4 秒一次、连续 2 次查不到就 `endSession('process-exit')`。实测 16 秒即结束。但 TigerVNC viewer 这类 GUI 程序在认证阶段会退出启动进程、派生新 PID，导致按旧 PID 查不到——窗口可能还在，会话却被回收。
   修复：`spawnDetached` 记录调起的 exe 文件名，PID 查不到时用 `tasklist /FI "IMAGENAME eq vncviewer.exe"` 按进程名兜底，仍有实例就认为会话继续。

2. **主窗口立即隐藏，认证框不显眼（体验 bug，已修）**
   调起成功后立刻 `mainWindow.hide()`，而 VNC 认证窗需要 1–3 秒才弹出，用户以为"点了没反应"。
   修复：延迟 1.5 秒再隐藏；若期间用户回到主控（窗口获得焦点）则取消隐藏。

3. **macOS 认证方式选错（配置问题，已补指引）**
   macOS 屏幕共享有两套独立认证：
   - **独立 VNC 密码**：需在「屏幕共享 → 电脑设置」勾选"VNC 查看器可以使用密码控制屏幕"单独设置；兼容所有 VNC 客户端，是本软件"记住密码"能生效的方式。
   - **Mac 账号登录**：走 Apple DH 安全类型（IANA type 30），需 TigerVNC ≥1.14 + Mac 用户名/登录密码。
   两者混用会报 `No matching security types` 或反复要密码。用户"没设置过独立 VNC 密码"，很可能一直在用 Mac 账号密码去连只接受 VNC 密码的端口。
   另注：「远程管理」与「屏幕共享」互斥，开了前者会让后者设置变灰。

## 三、问题二：记不住账号密码 —— 设计缺口

根因在 `src/main/protocols/vnc.ts`：VNC 适配器调起 viewer 时**只传 `ip::port`，从不使用 `request.password`**，只返回一句"请在窗口中手动输入 VNC 密码"。凭据虽然用 DPAPI 加密存进了数据库，但 VNC 链路根本不消费它——存了等于没存。这与 RDP 不同：RDP 会把 DPAPI blob 写进临时 `.rdp` 的 `password 51:b:` 字段实现免密。

次要原因：连接对话框每次打开都把 `username`/`password` 清空，且不查询已保存凭据回填，用户面对空框自然重新输入。

修复：
- 用 TigerVNC 支持的 `-PasswordFile` 参数传入密码文件。文件内容是 RFB VncAuth 规范的 8 字节 DES 混淆值（密码位反转作 DES key，加密 8 字节全 0），非明文。临时文件仅当前用户可读写，调起后随进程退出清理。
- 连接对话框回填已存用户名，并显示"已保存密码，留空则自动使用"；密码明文始终不进渲染层。

**兼容边界（必须如实告知）**：`-PasswordFile` 只对**独立 VNC 密码（VncAuth）**生效。若目标 Mac 用"账号登录（Apple DH）"，密码文件无效，仍需手动输入 Mac 用户名与登录密码——这是 RFB 协议与 Apple 私有扩展的限制，本软件不绕过。

## 四、附带修复：日志脱敏误伤

`hasPassword` 字段名含 `password` 子串，被脱敏器整体替换成字符串 `"[REDACTED]"`，导致日志无法判断"本次到底传没传密码"——正是这次诊断的第一个障碍。修复：布尔型存在性信号键（hasPassword/reused 等）保留 true/false；字符串型敏感值仍严格脱敏。

## 六、官方参数核实与实现要点

**参数名核实（避免"想当然写代码"）**：官方 TigerVNC vncviewer 手册（https://tigervnc.org/doc/vncviewer.html）在 OPTIONS 段明确列出：

> `−passwd, −PasswordFile password-file` — If you are on a filesystem which gives you access to the password file used by the server, you can specify it here to avoid typing it in.

同页说明参数名大小写不敏感、`-param=value` 为合法形式。因此适配器用 `-PasswordFile=<路径>` **是 vncviewer 客户端的合法参数**，不是服务端的 `−rfbauth/−PasswordFile`（后者在 `Xvnc/x0vncserver` 手册中，两者同名但角色不同，不可混淆）。VNC 密码文件由 `vncpasswd` 生成的就是 8 字节混淆值，客户端可直接消费，故 `writeVncPasswordFile()` 的输出格式与之一致。

**实现要点（`src/main/protocols/vnc.ts`）**：
- 仅当解析到的 viewer 路径含 `tigervnc` 时追加 `-PasswordFile`；RealVNC / TightVNC 语法不同，宁可降级手输，也不臆造参数导致 Viewer 拒绝启动（否则又变成"点了没反应"）。
- 明文密码只以临时混淆文件传递，不进 argv、不写日志；日志只记 `autoLogin` 布尔与文件哈希。
- 临时文件走 `scheduleTempFileCleanup()`：Viewer 进程退出后清理 + 30 秒兜底；调起失败立即清理。
- 返回消息如实区分三类：TigerVNC + VncAuth（自动登录）、非 TigerVNC（手动）、Apple DH（即便 TigerVNC 也需手输账号密码）。
- 失败文案改为 VNC 口径（屏幕共享/端口/Viewer 路径），不再沿用 RDP 的"Windows 专业版"提示。
