# LanDesk 运维保障方案（Phase 4）

> 编写：ops-sre｜依据：ops-monitoring.md｜场景定性：纯局域网、零云端服务端、零运维服务器的桌面工具。传统云服务 SLO 全部转译为「客户端本地健康度 + 分发渠道可用性 + 被控端环境依赖」口径。

## 0. 运维对象与场景转译
三条主线：A 客户端本地健康度（进程/崩溃/SQLite/发现连接链路）；B 分发渠道可用性（GitHub Releases/raw/Actions 产物）；C 被控端环境依赖（开机在线、RDP/VNC/rustdesk、端口、凭据、防火墙）。
指标转译：服务存活探针→客户端进程存活/崩溃率；HTTP 5xx→连接/spawn/配置失败率；P95 接口耗时→首屏/扫描/建链耗时；支付成功率→连接成功率（核心业务指标）；HTTPS 证书临期→代码签名证书临期；流量洪峰→扫描并发/CPU 保护。
健康度基线：主进程崩溃率≤0.1%、首屏可交互 P95≤2s、扫描 P95≤5s、核心链路可用率 100%（质量门禁口径）。

## 1. 部署与运行架构
服务端成本为零（无云主机/负载均衡/数据库）；分发 GitHub Releases；CI GitHub Actions；观测=本地磁盘 + 可选匿名遥测（默认关）。
逻辑拓扑：主控端 → 设备发现(mDNS/ARP/SSDP/端口扫描) → 局域网设备；spawn 外部进程 → 被控端桌面；SQLite(sql.js WASM)+safeStorage(DPAPI) → 本地配置/凭据(不上传)。
环境划分：dev / ci / pre-release / production；发布=打 tag+上传资产，回滚=撤 tag+指向上一稳定 Release。

## 2. 监控体系（三层）
2.1 可用性层：主进程崩溃率>0.1%观察/>1% P0；连接成功率<95%关注/<80% P1/<50% P0；spawn 成功率<95% P1；发现成功率<70% P1；分发渠道连续 2 次不可达告警。
2.2 性能层：首屏 P95>2s、扫描 P95>5s、建链 P95>基线 2 倍（均持续 10min→P2）；SQLite 慢操作>200ms；常驻内存>500MB 或 CPU>80% 持续 10min→P2。
2.3 业务层（核心）：连接成功率按小时环比，跌>30% 或绝对值<95% 立即关注；按被控端 OS 分组成功率骤降定向排查；发现量环比跌>30%；凭据读写成功率<99%；同类 Issues 1h≥3→P1。
2.4 日志规范：JSON 结构化（ts/level/module/event/trace_id/msg），一次连接全链路共享 trace_id；日志三分类（运行≥30天/审计≥6个月/崩溃）；脱敏红线（不记凭据明文、目标 IP 全文、屏幕内容、个人信息，IP 仅留网段）；与磁盘水位联动滚动清理。
2.5 遥测边界：默认关闭、显式勾选同意、可随时关闭清除；仅采集崩溃事件/功能成功失败计数/耗时分位/版本号/OS 类型；禁止采集设备地址/凭据/屏幕/文件/拓扑明细。

## 3. 告警规则表（级别/阈值/持续/渠道/动作）
P0：A1 发版崩溃率>1% 或 1h≥3 例（5min）→撤 Release+回退+公告+冻结 tag；A2 连接成功率<50%（5min）→三类排查树止血；A3 分发渠道连续 2 次失败（2min）→切备用渠道+公告。
P1：B1 连接率 50~80% 或环比跌>30%（15min）；B2 spawn 成功率<95% 或连续 3 次失败（5min）；B3 发现成功率<70% 或发现数跌>30%（15min）；B4 同类 Issues 1h≥3（即时）。
P2：C1 首屏 P95>2s；C2 扫描 P95>5s 或>15s 超时；C3 内存>500MB 或 CPU>80%；C4 代码签名证书临期 30/7/1 天；C5 配置凭据读写<99%。
治理纪律：文案含版本/OS/指标/当前值/建议动作；同类聚合收敛；误报率>30% 调优；小样本不自动 P0。

## 4. 稳定性保障
spawn 包 try/catch + error/exit 监听、路径参数白名单、主进程绝不崩溃；扫描总超时 15s/单主机超时/并发上限≤64/分片/取消令牌；SQLite 启动 `PRAGMA integrity_check`，失败降级默认配置+最近备份恢复，损坏原文另存 `.corrupt.<ts>`；配置带 schema_version 幂等 migration，迁移前快照失败回滚；凭据仅存密文。

## 5. 故障应急预案（发现→定位→恢复→复盘）
统一流程：告警/Issues/回访进同一通道→5min 初判+三连问→先止血后查因→48h 复盘（不追责追流程）；第一响应人+备份人。
- FF-1 大面积连不上：三类排查树（本地客户端类/被控端类/网络类），止血优先公告"切协议+手动输入 IP"。
- FF-2 发版后崩溃激增：标记 Release Draft/删资产+撤 tag→指向上一稳定版→Issue 置顶公告→收集转储定位→热修复重发。
- FF-3 GitHub Releases 不可用：临时渠道优先级 Gitee Releases→OSS 直链→官网直链→合规网盘；raw 切 jsDelivr；全渠道公告 SHA256；恢复后镜像一致性比对防投毒。
- FF-4 配置损坏/凭据丢失：最近备份恢复→降级默认配置保留 `.corrupt`→凭据重新录入；疑似泄露提示改密清除密文。

## 6. 备份与恢复
配置+设备列表+历史：变更时自动快照，最近 7 份归档 + 每日归档≥7 天；凭据密文随配置快照；用户可一键导出加密归档包；代码制品存 GitHub tag+Releases。RPO≈分钟级，RTO 新机≤10min/本地配置≤1min。每季度 1 次恢复演练，失败按 P1 修复。

## 7. 安全加固
仅连授权设备；凭据 DPAPI/Keychain 密文；spawn 白名单防注入；mDNS/SSDP 仅内网、扫描限速限内网网段防 IDS 误判；AGPL/GPL 组件不捆绑、License 审查进 CI、Dependabot 漏洞扫描；代码签名+SHA256；遥测默认关显式同意。

## 8. 成本（≈0）
云主机/存储/带宽 ¥0；Releases ¥0（单文件<2GB）；Actions ¥0（免费额度内）；遥测 MVP 不自建。护栏：Actions 达 80%/100% 提醒、单 workflow timeout、禁自触发递归、Release 资产大小上限校验、保留临时渠道预案；每月清理过期 artifact/草稿/废弃 tag。

## 9. SLA（承诺值+统计口径+度量）
客户端崩溃率≤0.1%（有效会话）；核心链路可用率≥99.5%；首屏 P95≤2s；扫描 P95≤5s；分发渠道尽力而为+备用兜底；问题响应 P0 15min/P1 30min/P2 当日。度量=遥测样本+崩溃转储+Issues+48h 回访+本地打点。

## 10. 上线后 48 小时 / 1 周回访检查清单
48h：崩溃率≤0.1% 无聚集；连接成功率≥99.5% 按 OS 均衡；三类外部进程各 OS 可调起；首屏/扫描 P95 达标；Releases 可达+签名有效+SHA256 一致；配置首次读写加密正常；告警通道实测可达。
1 周：趋势稳定误报已调优；Issues 分类归档共性问题进需求池；7 份快照滚动可导出导入；遥测隐私无投诉未同意零采集；证书有效期登记；FF-3 演练一次可切换；稳定性数据回填研发方案。

## 11. 上游衔接与冲突上报
无服务端不部署 APM/探针，以客户端本地日志+崩溃转储+可选遥测+GitHub Issues+外部渠道拨测构成等效观测链路；采样不足时人工回访判定替代自动阈值。下游：崩溃率/连接成功率/容量基线→增长运营师。
