## 三、B类·P0范围对齐（采纳选品 REQ-001~012）
P0 占比校验：P0=12，需求池总量≈23，占比≈52%≤60%，合规。

## 四、核心流程修订（外部调起版，补全断点）
启动 → 合规声明 → 设备发现/手动加IP → 设备列表 → 协议选择 → 凭据 → 调起外部客户端 → ★本产品退到后台/托盘，用户在 mstsc/VNC Viewer 中操作 → 外部客户端关闭 → 本产品回设备列表+记录历史。
异常分支：调起失败→提示改用VNC/重试/切换协议；外部端认证失败→清除缓存凭据重新调起；连不上→连通性自检（ping+端口探测）分类结论→跳被控端开启指引；用户中途回主控→托盘图标唤出，外部客户端仍运行。

## 五、验收指标修订
核心闭环成功率≥90%；设备发现命中率≥90%；平台识别准确率≥95%；调起时延P95≤3s；外部客户端调起成功率≥99%；一键重连成功率≥95%；连通性自检准确率≥90%；P0缺陷=0。
删除：键鼠映射正确率≥99%、剪贴板同步成功率≥95%（非本产品实现）。

## 六、团长裁决结果（2026-11-18）
1. **实现模型 → 采纳外部调起**（无 Rust 环境、AGPL/GPL 合规边界清晰、可落地，与用户拍板的多协议聚合路线一致）。若要求内嵌协议栈需回退功能与工期重估。
2. **会话基础操作归属 → 采纳建议**：需求项保留在池、实现主体标注外部客户端、本产品验收不含画面渲染与键鼠映射。
3. **REQ-12 编号错位 → 以选品洞察师原始需求池 REQ-001~012 为权威编号**，产物主理人 Rev1.1 编号作别名映射；REQ-012=手动加 IP，团长裁决由 P1 提升 P0。

## 七、被控端部署指引补充（配套文档，非开发任务）
- Windows：开启远程桌面、防火墙放行3389，账号需有远程登录权限
- macOS：开启屏幕共享(VNC)并授予屏幕录制权限（否则黑屏/无法共享）
- Linux：优先X11会话；Wayland下x11vnc受限，建议改TigerVNC或切回X11；放行5900+
- 飞牛OS(fnOS)：以端口探测结果为准开启/确认VNC；探测不通可走RustDesk占位方案
