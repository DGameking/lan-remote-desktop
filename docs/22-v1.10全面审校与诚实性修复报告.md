## 一、用户反馈的根因（16 秒"已结束"）

本机日志 `logs/lanDesk-2026-11-25.jsonl` 取证：

```text
05:39:33 发起连接 VNC 192.168.10.15，hasPassword=true
05:39:33 已调起 VNC Viewer pid=13996 autoLogin=true
05:39:45 外部进程存活检测：未找到进程（streak 1/2）
05:39:49 外部进程存活检测：未找到进程（streak 2/2）
05:39:49 session.ended reason=process-exit durationSec=16
```

`16s = 10s 启动宽限 + 2×4s 轮询确认`。但真正的问题不是"误判退出"，而是**状态语义从根上就是错的**：

| 环节 | 旧逻辑 | 为什么错 |
|---|---|---|
| 调起成功 | 立即写 `status=connected` | 只证明"进程启动了"，不等于"远程桌面已建立"。本架构不接管协议层，根本无法确认连上 |
| 进程退出 | `endSession('process-exit')` 写 `status=ended` | "已结束"暗示曾有会话、正常结束；用户看到 16s 已结束，误以为连上过 |
| 错误信息 | `errorMessage` 始终为空 | 失败原因无处可查，UI 错误信息列全是 `-` |

**结论**：这是设计缺陷，不是参数 bug。v1.7.1 加的"进程名兜底"只是试图减少误判退出，没有解决"把启动当连上"的语义谎言。

## 二、修复：会话状态诚实化（v1.10）

`src/main/session/manager.ts`：

1. 取消"短时/长时退出"的阈值二分（那只是把误导后移）——**任何外部客户端退出触发的回收，一律写 `status='failed'` + 中性可读说明**，明确"未能确认进入远程桌面"；只有用户主动点"结束会话"才写 `ended`。
2. 新增 `describeClientExit(protocol, elapsedSec)`：按协议给出可操作排查方向（VNC 点明独立 VNC 密码 vs Mac 登录账号；RDP 点明远程桌面权限；RustDesk 点明会话码/自托管服务器），**绝不回显密码/路径/IP**。
3. 事件日志区分：客户端退出写 `session.not-confirmed`（WARN），主动结束写 `session.ended`（INFO），上下文带 `finalStatus`。
4. 双判诊断增强：PID 失效但进程名仍存活时记 INFO（可据此确认 viewer 派生新 PID）；双判均未存活时记 WARN（含 pid/imageName/pidAlive/nameAlive），供用户导出诊断包定位。
5. 防竞态：`endSession(reason, expectedSessionId?)` 支持会话 ID 校验，旧轮询定时器不得误杀新会话。

`src/main/protocols/base.ts`：补 `setLastLaunchedImageName()` 测试注入点（与既有 `setLastLaunchedPid` 对称）。

| P0-2 | 手动添加抹掉识别结果 | `discovery/aggregator.ts` | 对已存在设备调 `upsertManualDevice` 时 osEvidence/端口/协议清空 | 用 `rowToDevice(old)` 为基底，只更新 name/online/时间戳 |
| P0-3 | 备份导入覆盖本地扫描数据 | `ipc/index.ts` | `{...row}` 覆盖会把本地 osHint/证据/端口/在线状态清掉 | 以本地 dup 为基底，只合并备份中非空的 name |
| P0-4 | 备份注入可执行文件路的 RCE 面 | `ipc/validators.ts` | `settings: payload.settings as unknown as AppSettings` 让伪造备份注入 `vncViewerPath`/`rustdeskPath`，导入后连接时被 spawn | 改用 `validateSettingsPatch()` 逐字段白名单 + 路径非法字符校验 |

## 六、诚实边界（继续有效）

- 本工具**只能调起外部客户端，无法确认远程桌面是否真正建立**——这是架构边界，不是可修的 bug。v1.10 让状态不再撒谎，但不能凭空获得协议层确认能力。
- 若用户要"真正确认连上"，需改变产品根基（自研协议栈/被控端 Agent），属 C 类方案三，默认不做（见 `docs/17`）。
- 旧的"已结束"历史记录不会被迁移改写（避免篡改历史事实）；v1.10 起新记录按诚实语义写入。
