# v1.8 显示模式与分辨率实现说明（2026-11-24）

## 一、背景：为什么要重做显示设置

用户提出需要"显示设置、分辨率设置、自动适应当前屏幕、以远程对象分辨率显示"。核对代码与官方资料后发现 v1.6 的 RDP 预设存在三处实质缺陷：

1. **`screen mode id` 语义错误**：代码注释写"adaptive=自适应会话尺寸（3 号）"，但微软官方 `.rdp` 属性里 `screen mode id` **只有 `1`（窗口）和 `2`（全屏）两个值，不存在 3**。实际 `adaptive` 与 `fullscreen` 都写成 `2`，用户选"自适应"进的其实全屏。
2. **分辨率被写死**：`buildRdpContent()` 在宽高缺省时强行写 `desktopwidth:i:1920` / `desktopheight:i:1080`。官方明确这两个属性不写才是"匹配本地设备"（Match the local device），等于把"自动适应当前屏幕"这条路堵死。
3. **缺官方自适应参数**：真正管自适应的 `dynamic resolution:i:1`（远程会话分辨率随本地窗口缩放变化）与 `smart sizing:i:1`（本地等比缩放适配窗口）此前一个都没写；VNC 链路则完全没有显示设置。

## 二、统一显示模式契约（DisplayMode）

新增 `src/shared/types.ts` 的 `DisplayMode` 四值，RDP 与 VNC 共用同一套语义：

| 模式 | 用户语义 | RDP 映射 | VNC(TigerVNC) 映射 |
|---|---|---|---|
| `fit`（默认） | 自动适应当前屏幕 | 窗口 `screen mode id:i:1` + `dynamic resolution:i:1`，不写死宽高 | `-Maximize`（最大化窗口贴合当前屏幕） |
| `native` | 以远程对象分辨率显示 | 窗口 + `smart sizing:i:1` + `dynamic resolution:i:0`，不写死宽高 | 不传尺寸参数（保持远程原生分辨率，Viewer 默认窗口行为） |
| `fixed` | 固定分辨率 | 窗口 + `desktopwidth/desktopheight:i:WxH` + `dynamic resolution:i:0` | `-DesktopSize=WxH`（请求服务端切换） |
| `fullscreen` | 全屏 | `screen mode id:i:2` + `dynamic resolution:i:1` | `-FullScreen -FullScreenMode=current` |

**契约要点**：
- `AppSettings.displayMode` 全局默认（新连接默认 `fit`），`ConnectRequest.displayMode` 会话级覆盖；不传时沿用全局。
- 旧字段 `rdpScreenMode`、`screenMode` 保留兼容：`normalizeDisplayMode()` 把 `fullscreen`→`fullscreen`，`adaptive`/`window`→`fit`，且新的 `displayMode` 优先。
- `fixed` 才写分辨率；`fullscreen` 且旧调用方显式带宽高时也写（v1.6 兼容）；`fit`/`native` 一律不写，交给系统协商。
- 宽高越界回落 1920×1080，不生成畸形参数。

## 三、官方资料依据

- **RDP `.rdp` 属性**（微软 Learn，Supported DS properties / RDP file settings）：
  - `screen mode id:i:<1|2>`：1=窗口，2=全屏。
  - `dynamic resolution:i:<0|1>`：1=本地窗口缩放时远程会话分辨率随之更新。
  - `smart sizing:i:<0|1>`：1=本地窗口等比缩放远程内容、不改变远程会话分辨率。
  - `desktopwidth` / `desktopheight`：指定远程会话分辨率，不写则匹配本地设备。
- **TigerVNC vncviewer 手册**（tigervnc.org/doc/vncviewer.html）：
  - `-Maximize`：最大化窗口。
  - `-FullScreen` / `-FullScreenMode=current`：全屏及使用哪块显示器。
  - `-DesktopSize=WxH`：请求服务端在连接时切换到指定尺寸（依赖服务端支持 SetDesktopSize）。
  - VNC 的远程分辨率由被控端 VNC 服务端决定，Viewer 只能"请求"切换，**与 RDP 由客户端直接指定会话分辨率不同**——这一点在 UI 提示与返回消息里如实说明。

## 四、兼容边界（必须如实告知）

- VNC 的 `fixed` 需被控端服务端支持 `SetDesktopSize`，否则维持远程原分辨率——非缺陷，是 RFB 协议能力边界。
- 非 TigerVNC（RealVNC / TightVNC）参数语法不同，`buildVncDisplayArgs()` 对其返回空数组保守降级为 Viewer 默认行为，不臆造参数导致 Viewer 拒绝启动。
- VNC 明文协议风险提示保持不变；`-PasswordFile` 免密只对独立 VNC 密码（VncAuth）生效的边界不变。
