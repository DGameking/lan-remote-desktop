# 12｜v1.3 可观测性与诊断方案

> 版本：v1.3.0｜日期：2026-11-18｜状态：随 v1.3.0 交付
> 目标：在**零遥测、无服务端**前提下，把「连不上 / 为什么慢 / 为什么没免密」变成可查、可导出、可交给 AI 分析的本地结构化数据。
> 配套：`10-v1.3底层架构与能力缺口梳理.md` §4 给出「AI 获取状态」的边界，本文是该边界的落地形态；字段命名沿用 `src/shared/types.ts` 的 `IpcResponse<T> { code, message, data }` 与 `domain:action` 通道风格。

---

## 1. 设计约束（先说清不能做什么）

- **零遥测**：不采集、不上传、不自动上报崩溃；日志仅本机保存 30 天。设置中保留一个默认关闭、当前不激活的预留开关（`telemetryConsent`，默认且恒为 false），仅为未来版本预留，**当前版本不产生任何上报行为**（不得让用户误以为开启后会上传数据）。因此「可观测性」只能是**本地产出 + 用户主动导出**，不是云端 APM、不是崩溃上报 SDK、不引入任何外发通道。
- **诊断导出纯本地**：主进程把诊断包写到 `userData/diagnostics/` **固定路径**，用户手动复制文本或自行提供文件，数据才会离开这台电脑；**不存在任何自动外发通道**。
- **向后兼容**：v1.2 及更早已有文本日志；v1.3 改为结构化 JSONL，但**仍兼容旧文本日志读取**，升级后历史排障信息不丢失。
- **最小侵入**：不引入新的运行时依赖，日志写入、查询、快照、导出都在 main 进程内完成。
- **不含凭据**：日志、`log:query` 结果、状态快照、诊断包一律**不含任何凭据、明文密码、DPAPI hex、safeStorage 密文**。

## 2. 日志字段规范（JSON Lines）

- 文件：`userData/logs/lanDesk-YYYY-MM-DD.jsonl`，UTF-8，一行一个 JSON 对象，追加写。
- 结构 `LogEntry`：

| 字段 | 类型 | 含义 / 约束 |
|---|---|---|
| `ts` | string (ISO 8601) | 事件时间，带时区 |
| `level` | `'debug' \| 'info' \| 'warn' \| 'error'` | 级别 |
| `module` | string | 模块标签，如 `discovery` / `precheck` / `credential` / `session` / `adapter` / `ipc` / `diagnostics` |
| `event` | string | 稳定事件名，如 `precheck.result`、`credential.decision`、`adapter.launch`、`session.failed` |
| `context` | object | 结构化上下文（IP / 端口 / 协议 / `durationMs` / `autoLogin` / `failureClass` 等），**写入前按 §3 字段清单处理** |
| `traceId` | string | 一次连接链路唯一标识，贯穿 预检 → 凭据决策 → 适配器调起；非连接类事件可省略 |

- 示例（示意；局域网私有 IP 按口径保留完整，凭据类字段绝不出现）：

```json
{"ts":"2026-11-18T10:12:03.120+08:00","level":"info","module":"precheck","event":"precheck.result","context":{"ip":"192.168.1.20","port":3389,"protocol":"rdp","reachable":true,"latencyMs":4,"attempts":2},"traceId":"c7f2a1"}
{"ts":"2026-11-18T10:12:03.136+08:00","level":"info","module":"credential","event":"credential.decision","context":{"protocol":"rdp","autoLogin":true,"reason":"saved-credential-reused"},"traceId":"c7f2a1"}
{"ts":"2026-11-18T10:12:03.402+08:00","level":"info","module":"adapter","event":"adapter.launch","context":{"protocol":"rdp","durationMs":266,"launched":true},"traceId":"c7f2a1"}
```

- **连接链路埋点**：`traceId` 把一次连接从「预检 → 凭据决策 → 适配器调起」串成一条可检索链路；记录 `durationMs`（阶段耗时）、`autoLogin`（是否走免密回填）、失败时的 `failureClass`（分类，如 `host-down` / `port-closed` / `credential` / `client-missing` / `policy-guard` / `skipped`）。诊断包内可按 `traceId` 还原一次完整连接。
- **`skipped` 语义**：RustDesk 预检被跳过时记为 `skipped`，不再被误显示为「端口不可达」。
- **IP 口径**：日志中的局域网私有 IP **保留完整**，这是按 `IP:端口` 串联并定位一次连接问题的诊断必需；状态快照与可复制诊断文本里则对**网段 / 本机路径做掩码 / 去用户名处理**（见 §3、§6）。两者刻意区分：日志只在本机留存，导出文本才可能离开本机。

## 3. 脱敏字段清单（与 v1.3 实际实现一致的准确口径）

> 早期文档曾笼统声称「路径、IP、主机名、凭据字段已做本地脱敏」，与代码不符：旧版 `rdp.ts` / `vnc.ts` / `fileshare.ts` 的 `logger.info` 实际把明文 IP 与临时 `.rdp` 路径写进日志。v1.3 由结构化日志统一按**下表**处理，**不再沿用那句笼统说法**。

| 类别 | 运行日志 `*.jsonl`（本机留存） | 状态快照 / 可复制诊断文本（可能离开本机） | 理由 |
|---|---|---|---|
| 明文密码 / `password` | **绝不写入** | **绝不写入** | 凭据红线 |
| DPAPI hex / `password 51:b:` / safeStorage 密文 | **绝不写入** | **绝不写入** | 可用于还原免密凭据，等同凭据 |
| 账号名 `username` | 脱敏（掩码） | 脱敏（掩码） | 属个人 / 账号标识 |
| 含用户名的本机路径（`userData` 绝对路径、`.rdp` 临时路径） | 去用户名 / 掩码 | 去用户名 / 掩码 | 防止泄露本机用户名与目录结构 |
| 共享名 / UNC 路径 | 脱敏 | 脱敏 | 同上 |
| 局域网私有 IP | **保留完整** | **网段掩码** | 日志保留用于诊断定位；导出文本更保守 |
| `spawn` 命令行参数 / argv | 不记录含敏感项的参数 | 同左 | 防密码经命令行泄漏 |
| 异常堆栈 / 自由文本 message | 过滤关键字后再写 | 同左 | 防第三方组件把敏感串带进堆栈 |

> 主机名 / 设备名不列入强制脱敏字段（局域网内设备标识，非凭据）；但状态快照对可识别信息做保守处理。具体掩码算法由实现常量定义；本文约定「哪些字段必须处理、日志与快照各自的口径」，不固定实现细节。所有处理在**写入磁盘之前**完成，内存中短暂存在的明文不落盘。

## 4. 轮转与保留策略

- **按天分文件**：`lanDesk-YYYY-MM-DD.jsonl`，跨天自然切分。
- **按大小分片轮转**：单文件达到实现定义的阈值即切分为带序号的分片（如 `lanDesk-YYYY-MM-DD.1.jsonl`），避免单文件无限增长。
- **保留 30 天**：启动时清理修改时间超过 30 天的 `.jsonl`；`log:query` 只检索保留窗口内的文件，与 README「日志仅保留最近 30 天」口径一致。
- **兼容旧文本日志**：查询与诊断导出时同时识别历史文本日志（`.log` / `.txt`），按行解析为只读记录或作为纯文本片段并入结果，标注其来源；升级后旧日志仍可查。
- **纯本地**：不压缩上传、不外发、不与任何远端同步。

## 5. 三个新 IPC 通道契约

三个通道均经 preload 白名单暴露，返回统一 `IpcResponse<T>`；入参做类型与范围校验，越界值收敛到边界而非报错。

### 5.1 `log:query` —— 日志查询

- 入参（均可选）：`level`、`module`、`timeFrom`、`timeTo`、`traceId`、`keyword`、`limit`。
- 约束：**默认 200 条、上限 1000**；`limit` 超出上限或非正数时收敛到边界；`keyword` 仅匹配 `event` 与按 §3 处理后的 `context` 文本；按 `ts` 倒序返回（最新在前）。
- 返回：`LogEntry[]`（含兼容读取的旧文本日志条目并标注来源）；**不含任何凭据类字段**。

### 5.2 `app:getDiagnostics` —— 运行状态快照

- 入参：无。
- 返回：`DiagnosticsSnapshot`（字段见 §6）。
- 只读、无副作用、**不含任何凭据、明文密码、DPAPI hex**；网段 / 本机路径按 §3 做掩码 / 去用户名处理。

### 5.3 `app:exportDiagnostics` —— 一键导出诊断包

- 入参：无必填项。
- 行为：在**固定路径** `userData/diagnostics/` 写入一份**自包含**诊断包（快照 + 按 §3 处理的近期日志片段 + 按 `traceId` 组织的连接链路 + 环境信息），并**同时返回可复制文本**。本轮**不弹** `dialog.showSaveDialog`、不提供导出前勾选包含项（见 §10 后续演进）。
- 返回：导出文件路径与可直接复制的诊断文本（供 UI「一键复制」）。
- 约束：导出**仅由用户主动触发**，软件不自动导出、不自动上报；主进程只写本机固定路径，**用户手动复制文本或自行提供文件，数据才会离开这台电脑，不存在任何自动外发通道**；文本已按 §3 处理但仍描述本机 / 局域网环境，是否分享由用户自行决定。

> 以上契约为字段与语义规范；具体类型定义以 `src/shared/types.ts` 最终落地为准。

## 6. 状态快照字段表（DiagnosticsSnapshot）

| 字段 | 含义 |
|---|---|
| `version` | 应用版本（v1.3.0） |
| `platform` | 操作系统平台（如 win32） |
| `arch` | CPU 架构（如 x64） |
| `electronVersion` | Electron 运行时版本 |
| `uptimeMs` | 本次进程运行时长 |
| `storeMode` | 存储模式（`sqlite` / `json`，是否发生 WASM 降级） |
| `protocols` | 各外部客户端/协议可用性（`ProtocolAvailability`，含 `available` 与 `detail`） |
| `counts.devices` | 设备数量 |
| `counts.credentials` | 凭据**条数**（仅数量，不含任何凭据内容） |
| `counts.sessions` | 会话记录数量 |
| `recentSessions` | 最近会话（协议 / 状态 / 起止时间 / 设备名 / 失败分类 / `traceId`） |
| `recentErrors` | 最近错误（时间 / 模块 / 按 §3 处理后的 message / 失败分类 / `traceId`） |

**明确不含**：任何凭据内容、明文密码、DPAPI hex、safeStorage 密文、含用户名的本地绝对路径（已去用户名）。**网段做掩码**（快照/导出文本口径），计数字段一律只给数量。

> **与日志口径区分**：日志为诊断定位**保留完整私有 IP**（见 §2、§3），状态快照与可复制诊断文本采用更保守的**网段掩码**；两者刻意不同，评审时勿混为一谈。

## 7. 诊断导出位置与「如何把状态交给 AI」

- 导出位置：`userData/diagnostics/` 固定路径（如 `lanDesk-diagnostics-YYYYMMDD-HHmmss.txt`），本轮不支持用户自选路径。
- 面板位置：设置页新增「运行状态与诊断」面板 —— 查看快照、查日志、导出诊断包、一键复制文本。

操作步骤（面向用户）：

1. 打开 **设置 → 运行状态与诊断**。
2. 点「刷新 / 查看快照」看当前状态；需要细节时用「查日志」按 级别 / 模块 / 时间 / `traceId` / 关键字 过滤，默认 200 条、最多 1000 条。
3. 点「导出诊断包」：文件写入 `userData/diagnostics/`，面板同时给出**可复制文本**。
4. 点「一键复制」把文本复制 → 粘贴给 AI；或把导出的文件交给能读本地文件的 AI；或直接读 `userData/logs/*.jsonl` 的相关片段贴给 AI。
5. AI 据此定位问题、给出优化建议；**AI 无法远程连接本软件**（见 `docs/10` §4）。是否采纳修改由用户/开发者决定。

> 三种获取状态的方式（与 README 第十节一致）：**设置页面板** / **导出诊断包** / **直接读 `userData/logs/*.jsonl`**。三者数据都只在本机，出不出本机完全由用户主动复制/导出决定；**不存在任何自动外发通道**。日志含完整内网 IP，直接贴片段给 AI 前请自行确认可接受。

## 8. 零遥测声明

- 当前版本（v1.3.0）**不采集、不上传任何诊断或遥测数据**，**不含崩溃自动上报**；日志仅本机保存、保留 30 天。
- 设置中保留一个默认关闭、当前不激活的预留开关（`telemetryConsent`，默认且恒为 false），仅为未来版本预留；**当前版本不产生任何上报行为**，不得让用户误以为开启后会上传数据（该开关文案由设置页另行同步）。
- 日志与诊断包 100% 本地产出于 `userData/`；软件不发起任何外发连接，**不存在任何自动外发通道**。
- 诊断导出是**用户主动、纯本地**行为：主进程写到 `userData/diagnostics/` 固定路径，用户手动复制文本或提供文件后，数据才会离开这台电脑。
- 是否把诊断文本交给 AI、交给谁，由用户一次主动复制 / 导出决定，软件不代发、不缓存到远端。
- 当前版本不提供任何上报通道；若未来版本要引入任何形式的诊断上报，须作为独立变更重新评估隐私影响、默认关闭并在发布说明中提前披露，不属于 v1.3.0 的范围或承诺。

## 9. 单测覆盖点（纯函数为主，可回归）

- **脱敏**：密码 / DPAPI hex / 账号名 / 含用户名路径 / 共享名 / argv 各类断言输出不含原文；异常堆栈关键字过滤生效；**并断言局域网私有 IP 在日志中保留完整**（诊断定位必需）、在状态快照 / 诊断导出文本中为网段掩码。
- **日志序列化**：`LogEntry` 六字段齐全、JSONL 单行可被 `JSON.parse`、`ts` 可解析、`level` 枚举合法。
- **轮转与保留**：超过阈值正确切分并命名、`mtime > 30 天` 文件被清理、当天文件保留。
- **旧文本日志兼容**：历史 `.log` / `.txt` 能被 `log:query` 识别并返回且标注来源。
- **`log:query` 过滤**：按 `level` / `module` / 时间区间 / `traceId` / `keyword` 命中正确；`limit` 默认 200、上限 1000 的边界收敛；结果不含凭据类字段。
- **traceId 链路**：一次连接的 预检 → 凭据决策 → 适配器调起 三事件共享同一 `traceId`；`durationMs ≥ 0`、`autoLogin` 为布尔、`failureClass` 分类正确；RustDesk `skipped` 不再被判为不可达。
- **快照红线回归**：字段齐全、计数字段为数量；**断言快照 JSON 与诊断导出文本均不含 `password` / DPAPI hex / 密文 / 含用户名绝对路径 / 完整网段**，且本机路径已去用户名。
- **导出**：落盘到 `userData/diagnostics/` 固定路径、返回文本与文件内容一致、可复制文本含快照要点；导出不触发任何外发调用。
- **零遥测回归**：断言 `telemetryConsent` 默认 false 且不触发任何网络 / 上报调用；导出与查询全程无外发。

> 不在本文范围：端口预检重试、管理页入口 SSRF 校验、WoL 魔术包、mDNS 类型解析、DPAPI hex 归一化、改用户名不误用旧密码等，其单测由各自实现模块覆盖；本文只约定日志与诊断侧的可测点。

## 10. 后续演进（本轮不做，写明理由，避免被当成遗漏）

| 演进项 | 本轮不做的原因 |
|---|---|
| 诊断导出支持 `dialog.showSaveDialog` 用户自选路径 | 本轮导出固定写 `userData/diagnostics/` 并返回可复制文本，已满足「一键导出」；自选路径涉及文件对话框生命周期与路径校验，属独立交互项 |
| 导出前勾选包含项（快照 / 日志片段 / 环境信息可裁剪） | 需额外的脱敏分级与打包配置；本轮先保证「自包含且安全默认」，避免默认导出遗漏或过度暴露 |
| 状态快照补 `capabilityMatrix` 静态能力矩阵副本 | 能力矩阵已在 `src/shared/types.ts` 的 `CAPABILITY_MATRIX` 与 UI 中作为唯一事实来源，快照再存一份会产生副本漂移风险，需先定「单一来源」策略 |
| 轻量在线心跳 / 收藏·别名·最近连接 / SMB `robocopy /Z` 断点续传 / WS-Discovery·NetBIOS 补主机名 | 属产品侧演进，逐项理由见 `docs/11` §6；本轮聚焦连接可用性与可观测性 |
