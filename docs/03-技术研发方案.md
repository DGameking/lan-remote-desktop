# 局域网跨平台远程桌面软件 — 技术研发方案

> 角色：全栈研发师（fullstack-engineer）｜Phase 1 产出
> 依据：tech-stack-architecture.md（逐章执行）；上游三要素已由团长确认
> 硬约束：Node 22 / Python 3.13 / Git / gh CLI，**无 Rust 工具链**；交付全案 + 可运行代码 + GitHub 公开仓库
> 产品定位：Windows 主控端（自研 GUI + 多协议聚合 + 局域网发现），被控端用各平台现成开源 Agent，**不自研被控端**

---

## 〇、方案总纲（先给结论）

1. **主控端 = 本地桌面单体应用，零云端、零服务端**：所有能力（发现、协议调起、配置、凭据）都在 Windows 本机进程内完成，不上微服务、不上数据库服务、不上消息队列。这是与"日活千级以内 MVP 默认单体"判据一致的选择。
2. **GUI：Electron**（Tauri 因环境无 Rust 直接出局）。
3. **语言：TypeScript + Node 22 全栈**（前后端同构、一人可 cover）。
4. **协议策略："外部调起 > 内嵌实现"**：MVP 真正落地的是「mstsc.exe 调起（RDP→Windows）」+「外部 VNC Viewer 调起（VNC→macOS/Linux/fnOS）」；RustDesk 做可选外部调起（占位增强）。**不自研任何协议栈**——这是本方案能在本环境落地为可运行代码的关键。
5. **存储：SQLite（sql.js WASM 实现，纯 JS 零 native 编译）+ Electron safeStorage（Windows 走 DPAPI）加密凭据**，兼顾关系型实体模型与 CI ABI 稳定（团长裁决采纳）。

## 二、系统架构

- **架构模式**：单机模块化单体，无服务端、无微服务。
- **分层**：Renderer(Vue3) → Preload(类型化 API 白名单) → Main(IPC路由/会话/协议适配/配置/发现) → 外部客户端进程。
- **发现链路**：扫描 → 网段计算 → 并发端口探测(3389/5900/21116，并发50、超时400ms) → mDNS → ARP → 聚合去重 → 增量推 UI。
- **连接链路**：选设备+协议 → 会话管理读配置 → 协议适配器生成参数 → spawn 外部客户端 → 记录历史。

## 三、模块划分

M1 ipc / M2 session / M3 protocols / M4 discovery / M5 store / M6 logger+shared。依赖单向无环。

## 四、数据模型

Device / Credential / SessionRecord / Settings，JSON Store 字段规范等同关系表，含时间戳三件套、软删除、状态机、冷热分离归档。

## 五、API 清单（类型化 IPC）

discovery:start/progress/stop、device:list/upsert/delete、credential:set、session:connect/list、app:getStatus。统一响应 `{code,message,data}`，通道带 `v1:` 版本前缀。

## 六、多端适配

主控 Windows（SmartScreen 未签名说明）；被控 Windows(RDP 3389)、macOS(VNC 需开屏幕共享)、Linux(x11vnc/TigerVNC，Wayland 注意)、飞牛OS(fnOS，5900+RustDesk)、可选 RustDesk(21116)。iOS/鸿蒙/小程序/Web 明确不做。

## 七、非功能性承诺

/24 扫描≤5s、单探测超时400ms、协议调起 P95≤3s（点击→外部进程成功拉起）、UI P95≤200ms、崩溃率≤0.1%、凭据 DPAPI 加密无明文、日志留存≥30天。

## 八、Top3 风险

1. 被控端服务未开 → 扫描标注+开启指引+手动添加+RustDesk 兜底
2. 外部客户端缺失 → 依赖检测+路径探测+手动指定+下载引导
3. ABI/体积 → 锁版本+零 native 依赖+CI 固定+asar

## 九、协议集成方案（核心）

| 协议 | 当期 MVP | 方式 |
|------|----------|------|
| RDP→Windows | ✅ 真正落地 | mstsc.exe 调起 + 临时 .rdp（密码不写 .rdp，可选 cmdkey 预置） |
| VNC→macOS/Linux/fnOS | ✅ 真正落地 | 外部 VNC Viewer 调起 + 路径探测 |
| RustDesk | 🟡 占位可选 | 调起本地客户端 + 依赖检测/引导 |
| FreeRDP / noVNC / 自研栈 | 🔴 延后 | 演进规划，不进 MVP |

## 十、设备发现实现

网段计算(os.networkInterfaces) + 端口扫描(net.connect 主力) + mDNS(bonjour-service 监听 _rfb/_rdp/_rustdesk) + ARP(arp -a 补充) + SSDP/UPnP(可选发现手段) + UDP 广播(可选默认关) + 聚合去重。

## 十二、打包与 CI

electron-builder NSIS + portable，x64，asar:true；GitHub Actions(windows-latest, node22) → npm ci → build → dist → softprops/action-gh-release。tag v1.0.0 触发 Release。

## 十三、安全与许可合规

凭据 DPAPI 加密、白名单授权、IPC 参数校验、spawn 用参数数组杜绝注入、审计日志≥30天。
**AGPL 边界**：RustDesk 仅命令行调起独立客户端（进程间调用不构成衍生作品），禁止内嵌/捆绑/修改其代码（否则 AGPL 传染）。TigerVNC/x11vnc(GPL) 不随包分发；noVNC 许可更正为 MPL-2.0（文件级弱 copyleft，仅对修改的 MPL 文件负开源义务，不传染主控主体）。本项目自研代码用 MIT/Apache-2.0。

## 十四、当期 vs 延后（FF09）

**必须当期**：Electron 骨架+Vue UI+端口扫描/mDNS+**手动添加设备 IP 兜底（P0 必备，多网卡/AP 隔离下 mDNS 失效时的必备降级路径）**+RDP(mstsc)调起+VNC外部调起+JSON Store+safeStorage+白名单+CI+AGPL 边界。
**可延后**：RustDesk 深度集成、FreeRDP/noVNC 内嵌、UDP 私有探测、代码签名、SQLite 迁移、遥测、多端主控、被控端一键部署。
