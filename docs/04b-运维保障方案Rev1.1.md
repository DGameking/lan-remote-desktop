## 0. 运维对象与场景转译

三条主线：
- **A 客户端本地健康度**：进程/崩溃/SQLite/发现连接链路。其运行健康数据首版唯一来源为**本地结构化日志（留存本机 ≥30 天，用户自愿提供）**【首版生效】。
- **B 分发渠道可用性**：GitHub Releases / raw / GitHub Actions 产物，外部拨测可达【首版生效】。
- **C 被控端环境依赖**：开机在线、RDP/VNC/rustdesk、端口、凭据、防火墙，靠用户反馈与回访判定【首版生效】。

指标转译：服务存活探针→客户端进程存活/崩溃；HTTP 5xx→连接/spawn/配置失败；P95 接口耗时→首屏/扫描/建链耗时；支付成功率→连接成功率（核心业务指标）；HTTPS 证书临期→代码签名证书临期；流量洪峰→扫描并发/CPU 保护。

健康度基线（客户端本地可测目标，团队聚合统计依赖 V2 遥测）：主进程崩溃率 ≤0.1%、首屏可交互 P95 ≤2s、扫描 P95 ≤5s、核心链路可用率 100%（质量门禁口径）。**首版这些指标由本地日志与 QA 环境打点验证，不通过云端聚合。**

## 1. 部署与运行架构

服务端成本为零（无云主机/负载均衡/数据库）；分发 GitHub Releases；CI GitHub Actions；观测 = 本地磁盘日志 + 外部渠道拨测 + GitHub Issues/Discussions/社群反馈【首版生效】；可选匿名遥测【V2 生效，首版不自建、不采集】。

逻辑拓扑：主控端 → 设备发现(mDNS/ARP/SSDP/端口扫描) → 局域网设备；spawn 外部进程 → 被控端桌面；SQLite(sql.js WASM)+safeStorage(DPAPI/Keychain) → 本地配置/凭据(不上传)。

环境划分：dev / ci / pre-release / production；发布 = 打 tag + 上传资产，回滚 = 撤 tag + 指向上一稳定 Release。

## 2. 监控体系（三层）

> **数据源总原则**：首版客户端健康度的唯一数据来源是本地结构化日志（用户自愿提供）+ Issues/社群反馈绝对数；任何要求「百分比分位数」的指标在首版都无法由团队侧计算，一律标注 V2。

**2.1 可用性层**
- 【首版生效·可观测】分发渠道可达性：外部拨测 GitHub Releases/raw，连续 2 次不可达即告警。
- 【首版生效·可观测】进程异常/启动即崩溃：以 GitHub Issues/Discussions/社群反馈绝对数（1h 内 ≥3 例同版本）与定性 P0 判定。
- 【首版生效·本地可测】主进程崩溃/连接/spawn/发现事件：本地结构化日志记录，用户自愿提供时用于定位；团队侧不做百分比聚合。
- 【V2 生效】崩溃率 >0.1% 观察 / >1% P0、连接成功率 <95%/<80%/<50%、spawn <95%、发现 <70% 等百分比阈值——遥测上线后启用。

**2.2 性能层**
- 【首版生效·本地可测】首屏、扫描、建链耗时与内存/CPU：本地日志与 QA 环境打点记录；团队通过用户自愿提供的日志/回访抽样了解，不做 P95 聚合告警。
- 【V2 生效】首屏 P95>2s、扫描 P95>5s 或 >15s 超时、建链 P95>基线 2 倍、SQLite 慢操作>200ms、内存>500MB/CPU>80%——遥测上线后自动聚合告警。

**2.3 业务层（核心：连接成功就是我们的「成交」）**
- 【首版生效·可观测】用户反馈量：GitHub Issues/Discussions/社群中连接类、崩溃类反馈的**绝对数**，同类 1h 内 ≥3 例 → P1 人工介入。这是首版唯一可跨用户聚合的业务信号。
- 【首版生效·回访】连接可用性、按被控端 OS 分布情况：通过 48h/1 周回访与客服式沟通抽样确认。
- 【V2 生效】连接成功率按小时环比跌 >30%、按被控端 OS 分组成功率骤降、发现量环比跌 >30%、凭据读写成功率 <99% 等百分比指标。

**2.4 日志规范**：JSON 结构化（ts/level/module/event/trace_id/msg），一次连接全链路共享 trace_id；日志三分类（运行 ≥30 天 / 审计 ≥6 个月 / 崩溃）；脱敏红线（不记凭据明文、目标 IP 全文、屏幕内容、个人信息，IP 仅留网段）；与磁盘水位联动滚动清理。**首版日志全部留在本机 userData/logs，不离开设备；无网络上报逻辑。**

**2.5 遥测边界（整体标注 V2 演进，首版不生效）**
> 【V2 生效】遥测默认关闭、显式勾选同意、可随时关闭并清除；仅采集崩溃事件/功能成功失败计数/耗时分位/版本号/OS 类型；禁止采集设备地址/凭据/屏幕/文件/拓扑明细。上报开关（设置→隐私的匿名诊断总开关 + 「包含崩溃转储」二级开关）、字段白名单、minidump 落盘与上传前脱敏、90 天上报留存、opt-in 同意率作为样本充分性参考（建议 ≥25% 方启用百分比阈值判定）——**以上全部为首版不具备能力，不得写入首版 README、不得作为首版验收放行项**。首版对外隐私声明统一为：「连接与凭据数据永不离开本机/局域网；当前版本不采集、不上传任何诊断数据。」

> 【源码事实注·Phase 4 收尾实证核查】源码中存在一个 `telemetryConsent` 布尔配置位（定义于 `shared/types.ts` 的 `AppSettings`、`DEFAULT_SETTINGS`、store 的 `BOOLEAN_KEYS`，默认 `false`），仅为预留字段位——**无 UI 设置页、无读取它的上报逻辑、无接收端点**，属"埋字段未实现功能"。该位默认 false 且无副作用，**不影响首版"零采集、零上报"隐私声明**；建议保留，V2 启用遥测时复用。除该字段位外，全项目无 telemetry/上报 SDK/网络上报逻辑。本注为精度校准，不改变本节任何结论。

## 4. 稳定性保障

spawn 包 try/catch + error/exit 监听、路径参数白名单、主进程绝不崩溃；扫描总超时 15s / 单主机超时 / 并发上限 ≤64 / 分片 / 取消令牌；SQLite 启动 `PRAGMA integrity_check`，失败降级默认配置 + 最近备份恢复，损坏原文另存 `.corrupt.<ts>`；配置带 schema_version 幂等 migration，迁移前快照失败回滚；凭据仅存密文。**【首版生效】** 以上均为本地实现，与遥测无关。

## 5. 故障应急预案（发现→定位→恢复→复盘）

统一流程：告警/Issues/回访进同一通道 → 5min 初判 + 三连问（近期是否发布/配置/签名变更？渠道是否正常？本地资源是否异常？）→ 先止血后查因 → 48h 复盘（时间线/根因/影响面/改进项含责任人与截止时间，不追责追流程）；第一响应人 + 备份人。

- **FF-1 大面积连不上**：三类排查树——①本地客户端类（版本/spawn/配置）②被控端类（在线/协议栈/凭据/防火墙）③网络类（同网段/VLAN 隔离/AP 隔离/mDNS 被禁）；止血优先公告"切协议 + 手动输入 IP"。**触发：Issues 反馈绝对数或定性无法连接【首版生效】。**
- **FF-2 发版后崩溃激增（九步，与发布方案 FF05 一致）**：①撤下 Release/标 Draft → ②删问题 tag（`git push origin --delete vX.Y.Z`）→ ③README 顶部置顶撤回说明 → ④下载页/自动更新指向上一稳定版 → ⑤Issue 置顶公告 → ⑥收集转储定位根因、出 hotfix → ⑦重发 hotfix 后重生成 `SHA256SUMS.txt` → ⑧同步撤下 FF-3 临时渠道问题版本资产 → ⑨复测通过重新发版。止血 <15min；决策人 release-manager 判定 + team-lead 双签（凭据泄露类安全事件先止血、30min 内补报）。
- **FF-3 GitHub Releases 不可用**：临时渠道优先级 Gitee Releases → OSS 直链 → 官网直链 → 合规网盘；raw 切 jsDelivr；**硬约束：临时资产必须与 Releases 同批次 CI 产物、同一 SHA256，禁止本地另打包，公告给出校验值**；启用后 1h 内做镜像与 GitHub 资产 SHA256 比对防投毒；**回滚时临时渠道资产一并撤下/替换为稳定版**。
- **FF-4 配置损坏/凭据丢失**：最近备份恢复 → 降级默认配置保留 `.corrupt` → 凭据重新录入；疑似泄露提示改密清除密文。

## 6. 备份与恢复

配置 + 设备列表 + 历史：变更时自动快照，最近 7 份归档 + 每日归档 ≥7 天；凭据密文随配置快照；用户可一键导出加密归档包（本地介质/私有云，作为「异地」）；代码制品存 GitHub tag + Releases。RPO ≈ 分钟级（变更即快照），RTO 新机 ≤10min / 本地配置 ≤1min。每季度 1 次恢复演练（导出→新机导入→连接授权设备验证），记录实际 RTO/RPO，失败按 P1 修复。

## 7. 安全加固

仅连授权设备；凭据 DPAPI/Keychain 密文、明文不落盘不上传；spawn 白名单防注入；mDNS/SSDP 仅内网、扫描限速限内网网段防 IDS 误判；AGPL/GPL 组件不捆绑（rustdesk/VNC 由用户自备）、License 审查进 CI、Dependabot 漏洞扫描；代码签名 + SHA256 防篡改。**首版不采集不上传任何诊断数据**（隐私声明与代码一致，见 2.5）；【V2】遥测默认关显式同意、脱敏上报。

> 日志调用约束：`logger.*(extra)` 会把对象 JSON 序列化落盘，所有调用点禁止传入凭据明文、连接目标完整 IP/主机名、局域网设备清单——否则绕过"不采集"承诺。

## 8. 成本（≈0）

云主机/存储/带宽 ¥0；Releases ¥0（单文件 <2GB）；Actions ¥0（私有仓库 2000 分钟/月免费额度内）；遥测后端 MVP 不自建【V2 按需评估免费层】。护栏：Actions 达 80%/100% 提醒、单 workflow 设 timeout、禁自触发递归、Release 资产大小上限校验（超限 CI 失败）、保留临时渠道预案；每月清理过期 artifact/草稿/废弃 tag 与无用令牌。月度预算 ¥0，用量异常（额度突增）即告警复盘。

## 10. 上线后 48 小时 / 1 周回访检查清单

**48h**：Issues/社群有无同版本聚集性崩溃（≥3 例→FF-2）；连接可用性按 OS 分布回访；三类外部进程（mstsc/VNC/rustdesk）各 OS 可调起；首屏/扫描本地打点达标；Releases 可达 + 签名有效 + SHA256 一致；配置首次读写加密正常无静默丢失；告警通道（电话/短信/IM）实测可达、第一响应人与备份人在岗。
