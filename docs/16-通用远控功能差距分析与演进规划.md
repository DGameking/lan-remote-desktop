# 16｜通用远控功能差距分析与演进规划

> 版本：v1.5.1｜日期：2026-11-22
> 触发：用户实测连接 macOS 报 `An object could not be cloned`（已由 v1.5.1 修复）后提出：**"一般远程桌面软件的功能我都需要这软件有"**。
> 目的：把这句诉求落到可决策的层面——逐项对照主流远控功能，说清"哪些能在本架构内做、哪些必须靠外部客户端、哪些要做就必须改变产品根基"，给出分版演进建议，由用户拍板，而不是含糊承诺"全都有"。
> 对照对象：RustDesk / ToDesk / TeamViewer / AnyDesk / 向日葵（商业与开源远控）；Windows mstsc / Apple 屏幕共享·ARD / VNC（系统原生）；mRemoteNG / Royal TS（连接管理）。只对照公开可见的产品形态与能力类别，不断言内部实现与性能数值。

---

## 〇、结论先行（必须诚实）

**LanDesk 不是、也不打算自动成为 RustDesk/ToDesk 那样的全栈远控产品。** 它现在的定位是"**局域网远程桌面编排器**"：负责发现设备、识别系统、选协议、托管凭据、调起系统/第三方自带的客户端、做诊断和回收；**画面渲染、键鼠传输、剪贴板/文件数据的实际搬移，全部由被调起的 mstsc / VNC Viewer / RustDesk 官方客户端承载**（见 `docs/02c`、`docs/10`、`docs/11` 冻结口径）。

由此，"一般远控软件的功能"必须拆成三类看待：

| 类别 | 含义 | 处理方式 |
|---|---|---|
| **A. 本架构内可做** | 纯主控端本地编排/UI/配置/诊断，不需要服务端、常驻 Agent、自研协议栈 | 纳入 v1.6+ 迭代，能做的应做尽做 |
| **B. 靠外部客户端实现** | 属于画面/键鼠/会话内数据通道，LanDesk 一旦调起客户端就完成使命 | 通过"选对客户端 + 传对参数 + 给指引"最大化，不自研 |
| **C. 要做就必须改变产品根基** | 会话码、P2P 打洞、中继、账号/2FA、无人值守 Agent、自研 E2EE、自研文件/剪贴板通道、会话录像 | **需用户明确拍板是否推翻定位**；默认不做 |

一句大白话：**A 类是我们欠你的、该补；B 类你其实已经在用，只是它由 mstsc/VNC Viewer 提供而非 LanDesk 自己画；C 类是把 LanDesk 变成另一个 ToDesk，那是另一个产品、另一个工程量级。**

## 一、主流远控功能全景与三类归属

标注：**【A】**本架构内可做 · **【B】**靠外部客户端 · **【C】**改变产品根基（需拍板） · **【已具备】**当前已有。

### 1.1 连接与会话

| 功能 | 归属 | LanDesk 现状 / 说明 |
|---|---|---|
| 设备自动发现 | 【已具备】 | L1/L2/L3 分层扫描 + 服务指纹 + mDNS/ARP，本地实现 |
| 按 IP:端口直连 / 快速连接 | 【已具备】 | 输入 IP 或 IP:端口即可连，不依赖扫描 |
| 协议自动推荐 + 手动切换 | 【已具备】 | 系统×协议能力矩阵，手动指定系统不被扫描覆盖 |
| 账密托管 + 免密直连 | 【已具备】 | DPAPI 加密，RDP 用 `password 51:b:` 注入 |
| 连接历史 + 一键重连 | 【已具备】 | v1.5 补齐，可按设备/协议筛选、清空 |
| 收藏 / 置顶 / 别名 / 分组 | 【A】 | 主流连接管理器标配（mRemoteNG/Royal TS 都有），LanDesk 缺；需给设备表加列，纯本地 |
| 标签页 / 多会话同屏管理 | 【A/B】 | 面板级的会话列表可做【A】；真正的多桌面同屏窗口属画面层【B】 |
| 最近连接 / 常用排序 | 【A】 | 复用历史数据加排序即可 |
| 断线自动重连 | 【B】 | 断线检测与重连发生在外部客户端内部；LanDesk 只能提供"一键重连"入口【已具备】 |
| 会话码 / ID 连接 | 【C】 | 需服务端会话路由，与无服务端根基冲突 |
| 地址簿云同步 | 【C】 | 需账号体系 |

### 1.2 画面与交互（整体属 B）

| 功能 | 归属 | 说明 |
|---|---|---|
| 画面渲染 / 键鼠控制 | 【B】 | mstsc / VNC Viewer / RustDesk 客户端承载，LanDesk 不渲染、不传输 |
| 全屏 / 自适应分辨率 | 【B】 | RDP 可通过 .rdp 预设（LanDesk 可传参【A】），切换在客户端窗口内 |
| 多显示器切换 | 【B】 | 同上 |
| 画质 / 带宽调节 | 【B/A】 | RDP .rdp 已有带宽自动检测；细粒度调节在客户端 |
| 缩放 / 旋转 | 【B】 | 客户端窗口行为 |
| 截图 / 录屏 | 【B】 | 会话内功能；会话录像【C】（需改定位，且涉及隐私） |
| 键盘映射 / 鼠标模式 | 【B】 | 客户端功能 |
| 全屏/分辨率预设选择 | 【A】 | 可在连接对话框提供预设，写进 .rdp 参数 |

### 1.3 文件与数据

| 功能 | 归属 | LanDesk 现状 / 说明 |
|---|---|---|
| 会话内剪贴板同步 | 【B/已具备】 | RDP 原生重定向（可开关）；VNC/RustDesk 由客户端提供 |
| 会话内文件拖拽 | 【B/已具备】 | RDP 磁盘重定向；VNC 标准无；RustDesk 客户端内 |
| SMB 文件通道 | 【已具备】 | 资源管理器打开 `\\IP\共享名`，不经手内容 |
| 断点续传传输 | 【C/B】 | `robocopy /Z` 可改善但仍靠系统；自研传输通道属【C】 |
| 远程打印 / 串口 / USB 重定向 | 【B】 | RDP 重定向能力，需在 .rdp 打开对应开关【A 可传参】 |
| 常驻跨设备剪贴板同步 | 【C】 | 需自研通道与常驻进程，与边界冲突 |

### 1.4 协作与运维

| 功能 | 归属 | 说明 |
|---|---|---|
| 文字聊天 / 语音 | 【B】 | 商业远控会话内功能；LanDesk 不提供会话内通信 |
| 多人协作 | 【C】 | 需服务端与账号体系 |
| 权限控制 / 访问密码 | 【C/B】 | 依赖被调起通道自身；LanDesk 不接管认证 |
| 无人值守访问 | 【C】 | 需被控端常驻 Agent，与冻结负向清单冲突 |
| 远程关机 / 重启 | 【C/A】 | 需被控端授权通道；WoL 唤醒【已具备】，关机不能靠纯扫描实现 |
| 远程命令执行 / 进程管理 | 【C/A】 | 可经 SMB/SSH 间接实现，但需新协议通道，独立评估 |
| 批量唤醒 / 批量操作 | 【A】 | 纯本地对多设备发 WoL，可做 |
| 会话备注 / 标签 | 【A】 | 给历史记录加备注字段，纯本地 |

### 1.5 安全与合规

| 功能 | 归属 | 说明 |
|---|---|---|
| 传输层加密 | 【B/已具备】 | RDP TLS+CredSSP/NLA（不降级）、RustDesk E2EE；VNC 明文风险已提示 |
| 凭据本地加密 | 【已具备】 | DPAPI / safeStorage，不存明文 |
| 合规声明 / 仅连授权设备 | 【已具备】 | 首次连接勾选，全局硬约束 |
| 审计 / 日志诊断 | 【已具备】 | 结构化 JSONL 日志 + 诊断包导出，纯本地 |
| 双因素认证 / 防暴力破解 | 【C】 | 需账号体系，明确不做 |
| 自研端到端加密 | 【C】 | LanDesk 不接触媒体流，不提供也不宣称 |
| 水印 / 隐私屏 | 【B】 | 会话内客户端功能 |

### 1.6 自动化与工程

| 功能 | 归属 | 说明 |
|---|---|---|
| 命令行调用 / 脚本 | 【A】 | 可提供 `landesk://` 协议或 CLI 参数直连，纯本地 |
| 配置 / 设备列表导入导出 | 【A】 | 纯本地文件读写，可做 |
| 批量扫描 / 定时扫描 | 【A】 | 纯本地调度 |
| 在线状态实时刷新 | 【A】 | 需解决 sql.js 写放大（状态翻转才落库 + 失焦降频），独立工程项 |
| 延迟测速 / 延迟历史 | 【A】 | 复用现有 probePort 结果持久化 |
| API / Web 控制台 | 【C】 | 需服务端，与定位冲突 |

## 二、A 类演进清单（本架构内可做，建议 v1.6 起）

按用户价值与实现成本排序：

| 优先级 | 功能 | 价值 | 工程量 | 依赖 |
|---|---|---|---|---|
| P0 | 设备收藏 / 置顶 / 别名 / 分组 | 设备多了之后最主要的管理痛点 | 中 | 设备表加列 + 迁移 + UI |
| P0 | 列表搜索 / 排序 / 筛选 | 快速定位设备 | 小 | 纯前端 |
| P1 | 配置 / 设备列表导入导出 | 换机迁移、备份 | 小 | 纯本地文件 |
| P1 | 会话备注 / 标签 | 历史可读 | 小 | 会话表加列 |
| P1 | 全屏 / 分辨率 / 画质预设 | 连接体验更贴近商业远控 | 小 | 写进 .rdp 参数 |
| P1 | 命令行 / 协议链接直连 | 自动化、脚本集成 | 中 | IPC + 参数解析 |
| P2 | 在线状态实时刷新 | 列表更"活" | 中 | 需先解决 sql.js 写放大 |
| P2 | 批量唤醒 / 定时扫描 | 运维效率 | 中 | 复用 WoL + 调度 |
| P2 | 延迟测速 / 历史 | 连接质量可观测 | 小 | 复用 probePort |

> 这些不做"会话内画面能力"，但能把"管理一堆远程电脑"的体验补齐到主流连接管理器的水平。

## 三、B 类"最大化外部客户端体验"清单

LanDesk 不自己实现这些，但可以做三件事让它更好用：

1. **选对客户端**：检测到系统/协议后，优先推荐原生体验最好的客户端（Windows→mstsc，mac→屏幕共享兼容的 VNC Viewer，跨系统可选 RustDesk）。
2. **传对参数**：把全屏、多显示器、画质、剪贴板、磁盘/打印重定向等开关写进 .rdp 或客户端参数（A 类里的"预设"即是这块）。
3. **给对指引**：被控端开启步骤、权限要求（macOS 屏幕录制权限、Linux x11vnc 限制）已内联在连接对话框，持续按实测反馈校正。

## 四、C 类"改变产品根基"清单（需用户拍板）

| 功能 | 要付出的代价 |
|---|---|
| 会话码 / P2P 打洞 / 中继 | 要建信令服务器 + 中继服务器 + 被控端常驻 Agent + 账号体系；从"零服务端、零遥测"变成有后端的服务 |
| 账号 / 2FA / 设备云同步 | 要建用户系统、数据库、合规（隐私/数据保护） |
| 无人值守访问 | 要装被控端常驻程序，各平台签名、自启、权限、升级维护 |
| 自研 E2EE / 文件通道 / 常驻剪贴板 | 要自研协议栈与密钥管理，且可能触碰 AGPL/GPL 许可 |
| 跨网远程 | 同上，且需要公网基础设施与运营成本 |
| 会话录像 | 隐私合规风险大，且需要画面层接管 |

**这些不是"加个功能"，是把项目重做成一个商业远控。** 若要走这条路，需先修订 `docs/02c` 冻结验收标准与 `docs/11` 负向清单，重新评估工程量、许可与运营成本。

## 五、分版建议与决策点

- **v1.6（A 类第一批）**：设备收藏/置顶/别名/分组 + 列表搜索排序 + 配置导入导出 + 会话备注 + 连接预设。做完即"管理体验对齐主流连接管理器"。
- **v1.7（A 类第二批）**：在线状态实时刷新（先解决写放大）+ 批量唤醒/定时扫描 + 延迟测速历史 + 命令行/协议链接直连。
- **B 类**：随每版按实测反馈校正客户端推荐、参数预设与被控端指引，不单独立项。
- **C 类**：**等用户明确拍板**。若选择做，v1.6 起暂停，先做产品重新定义与可行性评估。

> 请用户在两件事上拍板：① A+B 类是否按 v1.6/v1.7 推进（推荐）；② C 类是否要突破定位（默认不做，若要做需重新定义产品）。
