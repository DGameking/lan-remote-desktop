## 一、权威口径总纲

1. **端形态**：Windows 桌面主控端（唯一）+ 被控端各平台现成开源 Agent；纯局域网、无服务端、无公网、无账号。
2. **实现模型**：外部调起（能力集成）。RDP→调起 `mstsc.exe`；VNC→调起外部 VNC Viewer；RustDesk→V2 占位外部调起。主控端**不渲染远程画面、不自研协议栈、不录制视频流**。
3. **P0 权威编号**：REQ-001~012 连续 12 项无跳号（详见第二章）；P0 占需求池约 52%（≤60% 红线），无全 P0。
4. **安全合规（贯穿硬约束，P0）**：仅连接用户有权访问的设备；禁止打洞、弱口令爆破、绕过认证；凭据 DPAPI 加密、禁止明文；**首版零遥测（无上报模块、无 opt-in 开关），天然不外发任何数据**；V2 若启用遥测则默认关闭、显式 opt-in。
5. **实现主体标注**：REQ-003~006、REQ-010 的用户价值保留在池，实现主体=外部客户端；本产品只负责"发现→选协议→注入/调取凭据→拉起外部客户端→断开回收"。

### 平台识别"双轨口径"（团长预先裁决 + 研发确认，最终定稿）
- **双轨设计**：自动弱提示 + 一键手动纠正。Device.osHint 标注来源（`inferred`/`manual`）；支持手动指定平台并持久化、记住该设备协议偏好。首次连接让用户确认平台后记住，后续按记忆平台推荐——用户侧体验仍是"按平台自动推荐"。
- **P0 放行条件**：平台**可手动指定/纠正并持久化 + 纠正后协议推荐正确率 100%**。**自动识别准确率不设硬指标、不作放行门槛**（原"自动识别≥95%"目标值作废）。
- **研发确认的技术事实（协议层缺信息，非实现偷懒）**：RFB/VNC 握手仅版本 banner + ServerInit name，无 OS 字段；指纹最多识别服务端软件（TigerVNC/Apple VNC）≠平台；macOS/Linux/fnOS 全开 5900；fnOS 本身即 Linux 发行版，协议层不可区分；仅 Windows(3389) 可高置信识别（Linux 装 xrdp 会误判）。TTL/SSH 共存/hostname 关键词均为弱启发式且可伪造。
- **运营看板**：将"平台识别准确率≥95%"从质量红线移除，改为"纠正后协议推荐正确率100%"+"手动纠正率"观测项。

## 四、关键口径辨析（防止跨角色扯皮）

### 4.1 两个"时延"不是同一个指标
| 指标 | 口径 | 归属 | 用途 |
|---|---|---|---|
| 调起时延 P95≤3s | 点击→外部进程拉起（本产品可控） | **本产品 P0 验收项** | 测试官用例、研发性能目标 |
| 端到端感知时延 P95≤8s | 点击→用户看到可用画面（含外部客户端与被控端网络） | **运营看板观测项，非本产品放行项** | 运营质量看板、漏斗诊断 |
> 二者不冲突、不可混用。端到端超标先归因：调起段≤3s 但端到端>8s → 属外部客户端/被控端网络，非本产品缺陷。运营方案"连接时延 P95≤8s"按"端到端感知"理解，**研发/测试按 3s 口径验收**。

### 4.2 WSCS 北极星口径校准
- **问题**：运营方案定义 WSCS 成功 = "画面渲染且持续≥30s"。外部调起模型下主控端**不渲染画面、无法感知用户在外部客户端的操作时长**，原口径**不可观测**。
- **校准口径（可观测）**：一次 WSCS 计入需满足——成功拉起外部客户端，**且**满足任一存活信号：① 外部进程从拉起到退出存活 ≥30s（近似）；② 用户在托盘菜单主动"结束会话"（精确信号，需提供该入口）。二者取其一即计入，避免重复计数。
- **已知误差**：单实例复用会使进程存活时长失真（见第 5 章），故 ① 为近似、② 为优先精确信号；WSCS 作**趋势指标**，不作单会话精确计费。运营方案第 1 章需按此修订（已同步 growth-operator）。

### 4.3 发现机制与命中率分母（研发确认，定稿）
- **默认主路径（均 P0 默认启用）**：端口扫描 3389/5900 为**主力发现手段** + mDNS（bonjour-service，取设备名线索）+ 只读系统 ARP 表（`arp -a`，补充已通信设备）。三者默认开启——**不是"纯 ARP 主路径、端口扫描作降级"**。
- 可选增强：SSDP（非 P0）。不采用主动 ARP 扫描（原始包+Npcap，需管理员权限，与零依赖相悖）。
- 兜底：发现失败/跨 VLAN/AP 隔离 → REQ-012 手动添加 IP（P0）。
- **命中率分母 = 环境中"已开启 RDP/VNC 服务且网络可达"的设备数**（以端口扫描结果为准；nmap/arp-scan 仅抽样核对，**不作为放行前提**——团长裁决），端口扫描对此类设备命中率接近 100%，≥90% 可达标。代码侧发现主力即端口扫描 + 手动加 IP 兜底。
- **不计入分母**：未开远程服务的在线设备（手机/打印机/IoT）——按服务发现的固有边界，原理上发现不了，写入 README 管理用户预期；跨网段设备靠手动加 IP。
- 性能：/24 网段并发 50、超时 400ms，端口扫描 ≤5s + mDNS 收集 5~10s，合计 ≤15s，优于 10 分钟基线。

### 4.4 首版稳定性放行依据（零遥测下的替代方案，团长裁决）
> 首版 v1.0.0 **零遥测、无上报模块、无 opt-in 开关**（fullstack-engineer 与 ops-sre 源码实证，README 隐私 v1.5 定稿"无崩溃自动上报"）。凡依赖遥测的指标首版不可度量，稳定性放行改用以下三条**可观测**依据：
1. **定性 P0 判定**：启动即崩溃、数据丢失、凭据泄露——任一出现即不放行（人工可判，无需遥测）；
2. **GitHub Issues 绝对数**：同一版本 1 小时内 ≥3 例崩溃报告 → 阻断放行（Issues 为公开硬数据）；
3. **用户自愿提供的脱敏本地日志**：作为辅助证据，不作为强制门槛。
- 崩溃率 ≤0.1% 保留为**质量目标值**（不放松质量要求），标注"V2 遥测上线后可度量"，**不设首版放行门禁**。<0.5% 口径删除。

## 五、流程与异常分支补充（托盘态最终版）

- 主路径：调起成功后本产品退托盘常驻 → 用户点托盘菜单"回到设备列表"唤出主控（**主路径**）→ 记录会话并按需断开 → 回设备列表。
- 辅助路径：检测到外部进程 exit 时**不直接弹回**，先二次确认窗口状态（防 mstsc/VNC Viewer 单实例转交导致的假退出误判），确认会话确已结束才回收+记录历史。
- 异常分支全清单（每步有出口，无断点）：
  - 调起失败（未装/被拦截）→ 提示改用 VNC / 重试 / 切换协议 / 返回列表；
  - 外部端认证失败 → 清除缓存凭据重新调起 → 回凭据步骤；
  - 连不上（离线/服务未开）→ REQ-011 连通性自检分类结论 → 被控端指引 / 手动排查清单；
  - 扫描 0 台 → 3 步排查清单 + 一键重扫 + 手动添加 IP；
  - 用户中途回主控 → 托盘图标唤出，外部客户端仍运行可切回。

**隐私红线（P0 硬约束，违反即不通过验收）**：
- 遥测事件**绝不携带**：IP、MAC、设备唯一标识、设备名、画面内容、文件路径、凭据、网络拓扑。
- `device_id` 若需关联，只能用一次性随机 hash 或设备数量区间，不得可反推。
- **首版零遥测**：无上报模块、无 opt-in 开关、无上报端点、无相关 UI（fullstack-engineer 与 ops-sre 已直读源码实证；README 隐私 v1.5 定稿"无崩溃自动上报"）。
- **★ P0 验证项（首版必测）**：全流程操作（启动→扫描→连接→调起外部客户端→断开）+ 抓包验证**外发请求数 = 0**，**例外仅两类局域网内必要流量**：① 局域网设备发现（mDNS 组播 / UDP 广播 / TCP 端口扫描 3389·5900）；② 调起外部客户端连接被控端（RDP/VNC 到局域网目标 IP）。除此之外任何外发（含公网域名解析、日志上报、崩溃上报）均为 P0 缺陷。
- V2 若启用遥测：默认关闭、显式 opt-in、可随时关闭、被拒不二次询问，抓包验证未同意时外发 = 0（仍遵守上述不采字段清单）。
