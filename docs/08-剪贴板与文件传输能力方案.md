# 08｜剪贴板与文件传输能力方案（v1.1.0）

> 版本：v1.1.0｜日期：2026-11-18｜状态：已实现并发布
> 适用范围：LanDesk Windows 主控端，连接 Windows / macOS / Linux / 飞牛OS 局域网设备

---

## 1. 需求与设计原则

### 1.1 需求
在 v1.0.0 远程桌面基础上增加：连接电脑间的**共享剪贴板**、**文件传输**，并**优化连接**；要求**基于各自系统本身具备的功能**实现。

### 1.2 不可动摇的设计原则（沿用 v1.0.0 终裁）
1. **不自研协议栈**：主控端只调起本机已安装的外部客户端 / 系统组件。
2. **不捆绑 GPL/AGPL**：不内嵌、不修改、不随包分发 RustDesk（AGPL）、TigerVNC/x11vnc（GPL）。
3. **零遥测、零内容经手**：不读取、不缓存、不上传剪贴板内容或传输的文件。
4. **凭据安全**：密码不写 `.rdp`、不进进程命令行、不明文落盘。

### 1.3 关键判断
共享剪贴板与文件传输恰好都能由各平台**已有能力**提供，因此本方案不引入任何新依赖、不新开端口、不改变"纯局域网/无服务端"定位。唯一明确的边界外能力是"跨设备常驻剪贴板同步（断开会话后仍同步）"——它需要中心服务，与项目定位冲突，不做。

## 2. 分层能力模型

| 通道 | 共享剪贴板 | 文件传输 | 能力来源 | source 标记 |
|---|---|---|---|---|
| RDP（Windows↔Windows） | ✅ 会话内重定向 | ✅ 会话内磁盘重定向 | Windows RDP 原生 | `channel` |
| SMB 文件通道（全平台） | — | ✅ 资源管理器打开 `\\IP\共享名` | Windows 资源管理器 + 对端 SMB | `channel` |
| RustDesk（可选） | ✅ 会话内同步 | ✅ 客户端内文件传输 | RustDesk 官方客户端 | `client` |
| VNC（macOS/Linux/fnOS） | ✅ 取决于 Viewer | ❌ 标准协议无 | 外部 VNC Viewer | `client` / `unsupported` |

该矩阵在代码中以 `CAPABILITY_MATRIX` 常量为**唯一事实来源**（`src/shared/types.ts`），UI 提示、连接回显与本文档均引用它，避免口径漂移。

## 3. 各通道实现细节

### 3.1 RDP 剪贴板重定向
- 生成 `.rdp` 时写入 `redirectclipboard:i:1`（开）或 `i:0`（关）。
- 默认值 `AppSettings.clipboardSharing = true`，连接对话框可临时覆盖。
- 复制文本/图片在两台 Windows 电脑间直接生效，由 mstsc 与 RDP 协议承载。

### 3.2 RDP 磁盘重定向（会话内文件传输）
- 开启时写入 `drivestoredirect:s:*` + `redirectdrives:i:1`；关闭时写入空值 + `i:0`。
- 默认值 `AppSettings.driveRedirection = false`（安全默认关闭）。
- 效果：远程桌面会话内出现本机磁盘，可直接拖拽复制文件。
- 安全提示：被控端可访问被映射的本机磁盘，UI 明确警告"仅对可信设备开启"。

### 3.3 SMB 文件通道（跨系统文件传输）
- 新增 `src/main/protocols/fileshare.ts`：`buildUncPath()` 构造 UNC 路径，`openFileShare()` 调起 `explorer.exe \\IP\共享名`。
- IP 与共享名经 `validateFileTransferTarget` 严格校验（合法 IPv4 + 安全字符集，杜绝 `\ /` 与 `..` 路径逃逸）。
- 对端要求：开启系统自带 SMB 文件共享（Windows 文件共享 / 飞牛OS SMB 服务 / macOS 文件共享 / Linux Samba）。
- 常用共享名可存 `AppSettings.defaultShareName`，连接时自动填入。
- 全程不经手文件内容：LanDesk 只负责调起资源管理器。

### 3.4 RustDesk / VNC（客户端原生）
- RustDesk：剪贴板同步与文件传输由官方客户端原生提供，LanDesk 仅调起，UI 标注"客户端内使用"。
- VNC：剪贴板靠 Viewer 的 RFB CutText 能力；标准 VNC 无文件传输，UI 明确引导改用 SMB 通道或 RDP/RustDesk。

### 3.5 连接优化
- `src/main/discovery/precheck.ts`：`probePort()` 单次 TCP 探测，返回可达性与往返延迟；不发送任何协议数据。
- `PROTOCOL_PRECHECK_PORT`：RDP=3389、VNC=5900、RustDesk=0（跳过，因主要走 21116/中继，TCP 探测无意义）。
- 对话框在协议变化时自动预检，端口未开直接提示，避免盲目调起 mstsc/Viewer。
- RDP `.rdp` 加入 `bandwidthautodetect:i:1`、`connection type:i:6`（LAN）等局域网优化参数。

## 4. 安全与隐私边界

1. 剪贴板/磁盘重定向/SMB 访问均需用户在可信设备间自行开启，默认保守。
2. LanDesk 不读取、不缓存、不上传剪贴板内容与传输文件；日志不记录这些内容。
3. 合规声明：每次连接需确认"仅连接已授权设备"；SMB 对话框再次提示授权要求。
4. 共享名校验杜绝路径注入；UNC 路径只含 IP 与安全字符，不含凭据。
5. 密码仍不写 `.rdp`、不进命令行；SMB 访问凭据由资源管理器弹窗承载。
