## 基本字段
- **项目名称与一句话定位**：LanDesk — 一台 Windows 电脑，集中掌控局域网内所有异构设备（Windows/macOS/Linux/飞牛OS）。
- **平台选型**：Windows 桌面主控端（唯一）+ 被控端各平台现成开源 Agent；纯局域网、无服务端、无公网。

## 架构决策摘要（为什么选 A 而非 B）
1. **Electron 而非 Tauri/.NET**：环境无 Rust（Tauri 出局），团队 Node 栈可立即构建，electron-builder 打包成熟（加权 4.7 vs 2.9）。
2. **多协议聚合外部调起而非自研协议栈**：mstsc/VNC Viewer 成熟稳定、零协议攻关、合规边界清晰；自研栈超出范围。
3. **SQLite(sql.js WASM) 而非 JSON Store / better-sqlite3（团长复核裁决）**：sql.js 是编译为 WASM 的 SQLite，纯 JS 运行、零 native 编译，既满足 PRD 关系型实体模型（Device/Credential/ConnectionSession/Settings）又规避 better-sqlite3 的 CI ABI 风险，优于原 JSON Store 裁决。
4. **被控端用现成 Agent 而非自研**：自研 100~200+ 人日/数月 vs 现成 5~15 人日/数天（MVP 第三方优先）。
5. **RustDesk 降级 P2 外部调起（团长裁决）**：无 Rust 环境，调用官方编译 exe 即可，不进 V1.0 核心闭环。
6. **MIT/Apache-2.0 开源 + AGPL 边界厘清**：仅进程调起 AGPL/GPL 组件不构成衍生作品，不复制/不静态链接其代码。

## 🔧 v1.2.0 增量：可用连接版（2026-11-18）

- **需求来源**：用户强烈反馈 v1.1.0 是"完全无法使用的白板"，提四问：①连不上 ②无 IP:端口直连 ③发现不了各系统原生远程桌面能力 ④要识别+自动标识+自动完善端口+账密托管下次免密直连。
- **方案（全部基于系统原生能力）**：
  - 发现引擎：L1/L2/L3 分层扫描 + 服务指纹（RFB/SSH/HTTP/SMB/RDP 握手层只读识别），典型 /24 约 6-7s；mDNS 并行、ARP 存活种子。
  - 通用快速连接：输入 IP 或 IP:端口 直连，不依赖扫描。
  - 端口落地：Device.detectedPorts 记住发现端口，连接自动选用（老库 ALTER TABLE 迁移零丢失）。
  - 账密托管：RDP 用 DPAPI `password 51:b:` 免密（密码只经 stdin、不进 argv/明文/日志）；账密默认自动保存；下次点击同一设备免密直连；Credential Guard 明确降级不绕过。
  - 失败分类提示 + 按协议排查指引。
- **研究依据**：discovery-research（端口/banner 字节/分层参数/扩展点）、auth-research（DPAPI hex 格式/陷阱：safeStorage OSCrypt 不可复用、logoncredentials 非公开字段、VNC 密码属被控端）。
- **实现 commits**（待 push）：346f0dc 免密 / d2f1fcc 发现引擎 / f4180ce 快速连接 / 4a4d46b 端口落地+失败提示 / lead 本地账密自动保存闭环。
- **本地验证**：typecheck ✓ / typecheck:vue ✓ / test:unit 50/50 ✓ / build 三进程 ✓。
- **独立审查**：qa-integration（验证免密闭环/端口落地/扫描可用性/失败提示/回归风险）进行中。

## v1.3.0 增量：可观测性与直连增强版（2026-11-18）

- **需求来源**：在 v1.2「可用连接」基础上，回应三件事——能顺畅连上、失败能自己排查、运行状态可导出给 AI 据此优化；同时澄清「P2P 直连」口径、沉淀底层架构与能力边界。
- **交付功能（本轮实际交付，以 RELEASE_NOTES v1.3.0 段为准）**：
  - 可观测性：结构化 JSON Lines 本地日志（`userData/logs/lanDesk-YYYY-MM-DD.jsonl`，按字段清单脱敏 / 30 天保留 / 按大小分片轮转，兼容旧文本日志；局域网私有 IP 在日志中保留完整以便定位）+ `log:query` 查询 + `app:getDiagnostics` 快照 + `app:exportDiagnostics` 一键导出诊断包（返回可复制文本）+ 设置页「运行状态与诊断」面板。
  - 直连与管理：内网「管理页」入口，对扫描发现开放 Web 管理端口（如 8000/8001/548/5985）的设备用系统默认浏览器打开 `http://IP:端口`；仅内网 IP + 端口必须在该设备 `detectedPorts` 白名单内，防 SSRF，不开放任意 URL。
  - 链路埋点：`traceId` 贯穿 预检 → 凭据决策 → 适配器调起，记录 `durationMs` / `autoLogin` / 失败分类，可按 traceId 串起一次完整连接。
  - 连接可靠性：端口预检轻量重试（2 次，取最小延迟）、RustDesk `skipped` 语义（不再被误显示为「端口不可达」）。
  - QA 遗留修复：改用户名但密码留空时不再误用旧账号密码；DPAPI hex 大小写归一化，避免免密静默降级。
  - 体验：全局合规声明确认后连接对话框默认勾选（仍可取消）；RDP 免密限制明示（仅同一 Windows 用户会话有效，Credential Guard / 空密码账户自动回退手输，不绕过系统策略）；快速连接失败时按协议给出分类排查指引 + 端口预检按钮。
  - 直连增强补充（本轮第 11/12 项）：WoL 远程唤醒（UDP Magic Packet，best-effort 无回执、需 BIOS/网卡预开、跨网段无效，不引入常驻 Agent）；mDNS 服务类型扩展（含 UDP 类型 `_net-assistant` 与 `_device-info._tcp` TXT(`model`/`osxvers`) 解析），增强 macOS/Linux/NAS 识别——Windows 原生 RDP 默认不广播 mDNS，RDP 仍以 3389 + X.224 握手层指纹为主，飞牛OS 无稳定公开专属 mDNS 类型（靠 HTTP `Server` 头 + 5666）。
  - 诚实边界：Explorer 的 SMB 复制**不支持可靠断点续传**，现有「传文件」通道不承诺断点续传。
- **架构决策**：RDP/VNC/SMB 本就是 `IP:端口` 端到端直连、无任何中转，已是局域网内最低延迟路径；公网打洞 / 中继 / 信令 / 会话码 / 无人值守 Agent / 账号体系 / 2FA / 防暴力破解 / 自研 E2EE / 自研文件传输协议 / 常驻剪贴板同步 / 会话时长·码率·帧率统计 / 内建 SSH 或 VeNCrypt 隧道 / 内嵌 AGPL(GPL) 协议栈 / 崩溃自动上报 / 任何遥测外发 / VNC 画面自研渲染 均「明确不做」而**非能力缺口**（与无服务端、零遥测、不捆绑根基冲突，详见 `docs/10` 第五节与 `docs/11` 第四节）。本轮优化的是「让直连更顺、更可诊断、更安全」。
- **商业远控对照结论**：优秀体验建立在「被控端常驻 Agent + 云端信令/中继 + 账号体系」三件套上，本项目全部拿掉；**能借的是产品形态与工程规范（发现、唤醒、收藏、审计、日志），借不来的是协议能力（会话码、打洞、中继、2FA、E2EE、自有文件传输通道）**，严禁把后者写成「借鉴后已实现」。详见 `docs/11`。
- **AI 获取状态的边界**：软件无服务端、零遥测，AI 无法远程连进进程；落地为本地结构化产出 + 一键导出诊断文本，由用户主动贴给 AI 或让 AI 读本地文件，详见 `docs/12`。
- **零遥测与脱敏口径订正（据独立审查）**：`telemetryConsent` 字段与设置页开关保留但当前不激活、恒为 false，仅为未来版本预留，当前版本不产生任何上报行为；旧版 README「不含遥测开关」「路径/IP/主机名/凭据字段已做本地脱敏」两句与代码不符，已按 v1.3 结构化日志实际实现订正为——密码类字段、账号名、含用户名的本机路径、共享名脱敏，**局域网私有 IP 在日志中保留完整**（诊断定位必需），状态快照里的网段与本机路径做掩码 / 去用户名处理；诊断导出为用户主动、纯本地行为，主进程写 `userData/diagnostics/` 固定路径，不存在任何自动外发通道。
