## 基本字段
- **项目名称与一句话定位**：LanDesk — 一台 Windows 电脑，集中掌控局域网内所有异构设备（Windows/macOS/Linux/飞牛OS）。
- **平台选型**：Windows 桌面主控端（唯一）+ 被控端各平台现成开源 Agent；纯局域网、无服务端、无公网。
- **技术栈**：Electron + Vue 3 + Element Plus + TypeScript（electron-vite）；设备发现 bonjour-service(mDNS) + net/dgram 端口扫描 + arp 补充 + SSDP(可选)；协议 RDP(mstsc.exe 调起) / VNC(外部 Viewer 调起) / RustDesk(P2 占位外部调起)；存储 SQLite(sql.js WASM，零 native 编译) + Electron safeStorage(Windows DPAPI)；打包 electron-builder(NSIS)；CI GitHub Actions。

## 架构决策摘要（为什么选 A 而非 B）
1. **Electron 而非 Tauri/.NET**：环境无 Rust（Tauri 出局），团队 Node 栈可立即构建，electron-builder 打包成熟（加权 4.7 vs 2.9）。
2. **多协议聚合外部调起而非自研协议栈**：mstsc/VNC Viewer 成熟稳定、零协议攻关、合规边界清晰；自研栈超出范围。
3. **SQLite(sql.js WASM) 而非 JSON Store / better-sqlite3（团长复核裁决）**：sql.js 是编译为 WASM 的 SQLite，纯 JS 运行、零 native 编译，既满足 PRD 关系型实体模型（Device/Credential/ConnectionSession/Settings）又规避 better-sqlite3 的 CI ABI 风险，优于原 JSON Store 裁决。
4. **被控端用现成 Agent 而非自研**：自研 100~200+ 人日/数月 vs 现成 5~15 人日/数天（MVP 第三方优先）。
5. **RustDesk 降级 P2 外部调起（团长裁决）**：无 Rust 环境，调用官方编译 exe 即可，不进 V1.0 核心闭环。
6. **MIT/Apache-2.0 开源 + AGPL 边界厘清**：仅进程调起 AGPL/GPL 组件不构成衍生作品，不复制/不静态链接其代码。
