# 需求与平台选型报告 —— 局域网跨平台远程桌面控制软件

> 依据：requirement-analysis.md + platform-selection.md｜Phase 1 选品洞察师产出
> 三要素与路线已由团长确认，不再追问。

## 一、需求概述（五要素）

- 业务目标：一个 Windows 桌面程序，自动发现局域网内设备，按平台用合适协议直连桌面，无需公网、无付费中转。
- 目标用户：局域网内跨设备操作的个人与小团队（含用户本人）。唯一主角色=主控端操作者；被控端是"可访问资源"。
- 核心场景：同一局域网内，操作者坐 Windows PC 前 → 打开程序 → 列出在线设备 → 选目标 → 凭据 → 全屏/窗口操作远端桌面。
- 关键流程：启动 → 发现(mDNS/UDP/ARP/端口探测) → 列表 → 协议推荐 → 凭据 → 建连 → 会话操作 → 断开 → 记历史。
- 约束：①纯局域网；②主控自研 GUI、被控用现成开源 Agent；③Node22/Python3.13、无 Rust；④GitHub 公开仓库；⑤仅访问有权设备。
- 预算/时间假设：零到低现金、40~80 人日（8~14 周兼职）；若变化按第六章备选调整。

## 二、核心需求清单（KANO）

基本型 P0（MVP 必含）：REQ-001 自动发现、002 设备列表、003 Windows RDP、004 macOS VNC、005 Linux VNC、006 飞牛OS VNC、007 协议推荐+手动切换、008 凭据加密、009 历史+一键重连、010 会话基础操作、011 被控端指引+自检。
期望型 P1（V1.1）：012 手动加 IP（建议纳入 MVP，成本极低）、013 多会话标签、014 剪贴板、015 别名分组、016 分辨率适配、017 质量指示。
兴奋型 P2（V2.0）：018 文件传输、019 WoL、020 截图录制、021 多屏/音频、022 主题快捷键。
反向需求（坚决砍）：公网打洞访问陌生设备、未授权访问/爆破、自研被控端、复杂权限/账号体系。

MVP 范围：REQ-001~012 共 12 项 P0（<15 上限）。闭环：发现→认平台→用对协议→安全存凭据→连上操作→一键重连→连不上时有指引。

验收标准摘要：发现 5s 内列出设备、离线 30s 标记、RDP/VNC 正确凭据 10s 内进桌面、凭据 DPAPI 加密无明文、历史保留 50 条、平台默认协议 Win→RDP 其余→VNC、被控端按平台给出开启步骤+端口自检。

## 三、平台形态选型

四步设备习惯法结论：桌面/长时操作 + 底层网络能力 → **Windows 桌面软件（唯一主控端）**；被控端用现成开源 Agent。

七平台矩阵打分（合计）：桌面软件(Win) **33** > 跨端App 20 = 鸿蒙 20 > Web 19 = iOS 19 > 公众号H5 16 > 小程序 13。桌面全面领先：Web/小程序无法做 mDNS/广播/协议栈/键鼠注入，且无公网约束排除托管 Web；小程序需备案连不上局域网 IP；桌面自分发（GitHub Releases）零审核秒级发版。

被控端自研 vs 现成：自研 100~200+ 人日/数月/全平台权限坑；现成 5~15 人日/数天~两周 → 选现成（MVP"第三方优先"）。

GUI 技术栈：首选 Electron+TS（复用 Node22，net/dgram 发现、keytar/DPAPI 凭据、electron-builder 分发）；备选 Python/PySide6；Tauri/RustDesk 核心需 Rust（缺失）列 V2。

决策树路径：需求合法（限自有设备）→ 桌面/长时 → 桌面软件 → 无 B 端后台 → **Windows 桌面软件 + 被控现成 Agent**。
机会：竞品偏公网/单协议，"纯局域网+零配置发现+多协议聚合+单一 Win 程序+开源自分发"是差异化空位。
一票否决风险：任何导向未授权访问的能力。

## 四、可行性四维

- 技术：可行，中低风险（成熟组件可承接；攻关点在发现稳定性/VNC 方言兼容/被控环境差异）。
- 成本：中风险（预算待定）。开发 40~80 人日；运行 0 元/月；代码签名证书可选；不上架无需软著。≤20 人日则降配为"RDP+VNC+最简发现+手动加 IP"。
- 时间：低风险，约 8~14 周（可裁剪版约 6 周），无商店审核/ICP 瓶颈。
- 合规：中风险。用途红线——不内置未授权访问、不公网打洞、首次启动声明"仅连有权设备"、凭据本地不上传。许可证——RustDesk AGPL-3.0、TigerVNC/x11vnc GPL-2.0、noVNC MPL-2.0、FreeRDP Apache-2.0；以外部进程调起不构成衍生作品，禁止复制/静态链接；主控端用 MIT/Apache-2.0。

风险汇总：技术 中低 / 成本 中 / 时间 低 / 合规 中。

## 五、待确认问题（未决，按影响降序）

1【高】预算上限（现金+人日）？2【高】上线时间？3【高】许可证策略（外部进程集成/主控宽松许可）？4【高】被控设备盘点（系统版本/VNC-RDP 是否已开/是否同网段）？5【中】GUI 栈 Electron vs PySide6 vs Tauri？6【中】网络环境（多子网/VLAN/AP 隔离/IPv6）？7【中】仓库命名/README 语言/LICENSE/是否提供被控一键脚本？8【中】MVP 是否含手动加 IP？9【低】文件传输/剪贴板是否进 V1.0？10【低】macOS 权限引导文档？

## 六、结论与建议

唯一主推荐：**Windows 桌面软件（Electron+TS 自研 GUI，唯一主控端）+ 被控端各平台现成开源服务/Agent**；MVP=REQ-001~012（12 项 P0）；值得做。

备选：A(V2) Tauri+Rust 追求体积性能；B(过渡,不主推) 纯开源客户端组合+发现脚本，体验割裂不满足"单一程序"；C(V2 扩端) Flutter/RN 查看器。
明确否决：Web/小程序/App 作首版主控端。
预算/时间收紧仅触发功能裁剪，不改端形态；许可证策略影响 LICENSE 但不改端形态。
