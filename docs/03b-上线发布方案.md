# LanDesk 上线发布方案（Phase 3）

> 编写：release-manager｜依据：release-deployment.md｜唯一渠道 GitHub Releases（无应用商店、无服务端）
> 门禁前提：P0 bug=0、核心链路 100%（Phase 2）。门禁未达标则拒绝发布并上报团长。

## 0. 发布结论
Windows 桌面程序，纯局域网、无账号、无支付、无 UGC、无云端 → App Store/华为/小程序等商店审核要点**全部 N/A**。事实上的"审核"是 Windows SmartScreen 与开源许可合规，已逐项告知。唯一渠道 GitHub Releases，秒级发版、当天 hotfix。

## 1. 环境与渠道
四套环境映射：dev(本机 npm run dev) / test(PR 触发 Actions check，失败禁合并) / staging(vX.Y.Z-rc.N→Prerelease 内测) / prod(vX.Y.Z→Release draft→Publish)。
分发资产三件（实际命名，2026-11-18 源码复核确认）：`LanDesk-1.0.0-setup-x64.exe`、`LanDesk-1.0.0-portable-win-x64.exe`、`SHA256SUMS.txt`。CI glob 通配与校验值步骤不受影响。无服务器/数据库/域名/备案/HTTPS 证书需求。

## 2. CI/CD 流水线（.github/workflows/build.yml）
tag(v*) 或 workflow_dispatch → checkout → setup-node@v4 + node-version 22 + cache npm → npm ci → 质量卡点(typecheck+lint+test:unit) → tag 与 package.json 版本一致性校验 → npm run build → npm run dist -- --x64（dist 脚本已含 --win，不再重复传）→ 生成 SHA256SUMS.txt → 资产完整性自检 → upload-artifact → softprops/action-gh-release(正式版 draft，rc 标 prerelease) → 人工 Review → Publish。
四硬卡点：npm ci 锁依赖、质量门禁、版本一致性、资产非空。生产资产必须本次 CI 产出，禁止本地打包直传。CI 仅用 secrets.GITHUB_TOKEN(contents:write 最小化)，无硬编码密钥。.gitignore 含 node_modules/dist/out/*.env/.env.*/*.pem/*.pfx。

## 3. 版本与发布流程
SemVer：主版(架构破坏)/次版(新协议发现能力)/修订(bug)。tag：v1.0.0 正式 / v1.1.0-rc.1 预发 / v1.0.1-hotfix.1 紧急。
流程：rc tag→Prerelease 内测冒烟→正式 tag→draft→人工 Review(资产/SHA256/Notes/合规)→Publish(工作日上午)。首版全量发布理由：冷启动无存量用户、已过 rc 最低灰度档。

## 4. 回滚预案（FF05）
触发：P0(数据丢失/凭据泄露/无法连授权设备/启动崩溃)、24h 内集中无法运行反馈、资产校验不一致。决策人 release-manager 判定 + team-lead 双签；安全事件可先止血后 30min 补报。
五步：<15min 止血——Release 切 draft→删 Release+tag→确认上一稳定版 latest(首版走 hotfix)→README 置顶公告+Issue→出 v1.0.1 修复版。
数据兼容：SQLite schema 向后兼容(先加列后删)；safeStorage DPAPI 密文与 Windows 用户绑定，回退须同用户；回滚只换程序不动用户数据。首版保留可立即重出的 hotfix 分支与 CI。

## 5. 合规风险（FF05）
5.1 SmartScreen 未签名告警（最高发）：README/Release Notes 写引导——"更多信息→仍要运行"、属性解除锁定、防火墙选专用网络。首版未签名已知且接受，不隐瞒。中期可申诉误报，长期 EV/OV 证书(¥1000~3000/年，EV 即刻建立声誉)。**团长决策：首版不签名。**
5.2 README 必备声明：仅连拥有/明确授权设备；无后门不中转不上传；MIT/Apache-2.0 + THIRD_PARTY_NOTICES.md。
5.3 AGPL/GPL 边界复查清单：外部进程调起不捆绑不内嵌不静态链接；dist 内无 rustdesk.exe/VNC Viewer；未安装给引导而非随包分发；不改其源码；自研许可文件齐全。
5.4 前置核验：签名(N/A 首版)、iOS/Android/小程序域名证书(N/A)、Mark-of-the-Web/SmartScreen(适用)、防火墙端口 mDNS5353/SSDP1900/端口扫描(适用)。
5.5 商店审核要点全部 N/A，事实审核=SmartScreen+许可合规。

## 6. 发布前检查清单（12 项）
1 门禁 P0=0 且核心链路 100%；2 tag 版本一致；3 产物 Setup+portable 60~90MB asar 生效；4 Windows Defender 扫描无报毒；5 SHA256SUMS.txt 生成且抽查一致；6 文档齐全(README/LICENSE/THIRD_PARTY_NOTICES/RELEASE_NOTES)；7 核心链路冒烟(发现/三种调起/SQLite/safeStorage/安装+便携)；8 AGPL/GPL 边界复查；9 证书签名标注+SmartScreen 文案就位；10 git 历史无密钥泄露；11 回滚演练一次；12 工作日上午窗口+责任人就位。

## 7. 发布后动作与交接
Release 公告(Discussions/Issues 置顶)、从公开页重下三件资产校验 SHA256、核对 latest 徽章。48h 监控窗口交接 ops-sre：T+30min/T+2h/T+24h/T+48h 四时点，纯局域网无云端遥测，以 GitHub Issues/Discussions/社群反馈为准；48h 内 P0 即触发回滚。发布材料 24h 内归档保留 ≥1 年(发布单/制品记录/校验值/合规复查/观察报告)。
