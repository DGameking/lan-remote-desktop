# LanDesk

> 一台 Windows 电脑，集中掌控局域网内所有异构设备。

LanDesk 是一款运行在本机 Windows 上的**局域网远程桌面主控端**：聚合 RDP / VNC / RustDesk 三种协议，集中发现并连接 Windows、macOS、Linux、飞牛OS(fnOS) 桌面。

**纯局域网 · 无服务端 · 无公网中转 · 无账号 · 不上传任何设备信息。**

## 二、它能做什么

- **分层扫描 + 服务指纹**：L1 快速探存活（22/445/3389/5900/5666）、L2 长尾端口补扫、L3 服务指纹识别；VNC 读 RFB 横幅（`RFB 003.889`→macOS）、SSH 读 banner→Linux、HTTP Server 头→飞牛OS，真正识别"这是什么系统的原生远程桌面"，典型 /24 约 6-7 秒。mDNS 并行 + 只读 ARP 补充。
- 按 IP 聚合去重，自动推断平台与已发现服务端口（如 VNC 在 5901 会记住并在连接时自动使用）。
- 卡片 / 表格双视图，展示在线状态、可用协议、已发现服务与来源。
- **通用快速连接**：直接输入 IP 或 IP:端口（如 `192.168.1.20:5900`）即可连接，不依赖扫描；端口按协议智能预填、可手改。
- 外部客户端调起：RDP→系统 `mstsc.exe`，VNC→本机 TigerVNC/RealVNC/TightVNC Viewer，RustDesk→官方客户端（可选）。
- **账密托管 + 免密直连**：连接时输入账号密码即自动以 DPAPI 加密保存（可关）；下次点击同一设备直接进桌面，无需重复输入。RDP 用系统 DPAPI 生成 `password 51:b:`，密码只经 stdin、不写明文 .rdp、不进命令行。RDP 免密仅在**同一台主控机、同一个 Windows 用户**会话有效，Credential Guard / 空密码账户自动回退手输，不绕过系统策略。
- **连接可靠性**：连前端口预检（轻量重试 2 次、取最小延迟）+ 延迟显示，失败按原因分类提示（未开机/服务未开/非专业版/防火墙/凭据错/未装客户端）并自动展开排查指引；快速连接失败时附「端口预检」按钮可重测；RustDesk 预检跳过标记 `skipped`，不再被误显示为"端口不可达"。
- **共享剪贴板**：RDP 会话内剪贴板重定向（可开关）；VNC/RustDesk 由外部客户端原生提供。
- **文件传输**：RDP 会话内磁盘重定向（可开关），或用 Windows 资源管理器直接打开对端 SMB 共享（全平台）。**Explorer 的 SMB 复制不支持可靠断点续传**，现有「传文件」通道不承诺断点续传，大文件中途失败需重新复制。
- **运行状态与诊断**：设置页「运行状态与诊断」面板可查看运行状态快照、按级别/模块/时间/`traceId`/关键字查日志、一键导出诊断包并复制文本；三种获取状态的方式见第十节。
- **内网管理页入口**：对扫描发现开放了 Web 管理端口（如 8000/8001/548/5985）的设备，用系统默认浏览器打开 `http://IP:端口`；严格防 SSRF，见第十一节。
- **连接链路可追溯**：`traceId` 贯穿 预检 → 凭据决策 → 适配器调起，记录耗时、是否免密、失败分类，可在诊断包里按 `traceId` 串起一次完整连接。
- **WoL 远程唤醒（v1.3 新增）**：对已发现 MAC 的设备发送 UDP Magic Packet（**102 字节 = 6×0xFF + MAC×16**）尝试开机，**零新增运行时依赖、零服务端**；**best-effort、无送达回执**，需被控端 BIOS/网卡预先开启 WoL 且接有线，**仅同网段有效**，跨网段/无线通常不生效；**不宣称「设备已开机」**，也不引入被控端常驻 Agent。
- **mDNS 服务类型扩展（v1.3 新增）**：补充含 UDP 类型的服务发现（`_net-assistant`）与 `_device-info._tcp` 的 TXT(`model`/`osxvers`) 解析，配合 `_rfb`/`_smb`/`_ssh`/`_afpovertcp` 增强 macOS / Linux / NAS 识别；Windows 原生 RDP 默认不广播 mDNS，RDP 仍以 3389 端口 + X.224 握手层指纹为主（详见 `docs/11`）。
- 手动添加 IP（多网卡 / AP 隔离导致发现失败时的必备兜底路径）。
- 连接历史本地留存；**结构化 JSON Lines 本地日志**（`userData/logs/lanDesk-YYYY-MM-DD.jsonl`，按字段清单脱敏、仅保留最近 30 天、按大小分片轮转，兼容旧文本日志读取）。**当前版本零遥测**：不采集、不上传、不自动上报崩溃；设置中保留一个默认关闭、当前不激活的预留开关（仅为未来版本预留，当前版本不产生任何上报行为）。

明确**不做**：会话码 / P2P 打洞 / 中继 / 信令服务、无人值守常驻 Agent、账号体系 / 2FA / 防暴力破解、自研端到端加密（由被调起的通道提供，LanDesk 不提供也不宣称提供）、自研或内嵌协议栈（含 AGPL/GPL 栈与 VNC 画面自研渲染）、自研文件传输协议、常驻剪贴板同步、会话时长·码率·帧率统计、内建 SSH 或 VeNCrypt 隧道、移动 / iOS / 鸿蒙主控、账号云同步、会话录像、崩溃自动上报与任何遥测外发。RDP/VNC/SMB 本就是局域网内 `IP:端口` 端到端直连、无任何中转，已是延迟最低的路径，无需也不引入打洞或中继。剪贴板与文件传输均复用系统/客户端原生能力，LanDesk 不自研传输协议、不缓存其内容。完整取舍理由见 `docs/10`、`docs/11`。

## 四·补、如何连接一台设备（v1.2.0）

有四种入口，任选其一：

1. **扫描后点连接（推荐）**：设备发现页点开始扫描 → 识别出的设备会标注系统类型与已发现服务 → 点「连接」→ 协议和端口已自动按发现结果填好（如 VNC 在 5901 会自动用 5901）→ 输入账号密码 → 勾选合规 → 连接。账号密码默认自动保存到本机，下次点同一设备直接进桌面，无需再输。
2. **快速连接（不依赖扫描）**：点「快速连接（输入 IP:端口）」→ 输入 `192.168.1.20` 或 `192.168.1.20:5900` → 自动解析 IP / 端口 / 协议 → 填账号密码 → 连接。同样支持自动保存、下次免密。
3. **传文件**：设备卡片点「传文件」→ 用资源管理器打开对端 SMB 共享（详见第五节补充）。
4. **手动添加设备**：多网卡 / AP 隔离导致扫描不到时，在设置里添加 IP，再用快速连接指定端口。

**首次连接后如何免密**：只要输入了账号密码且"自动保存账号密码"开关开启（默认开），凭据就以 Windows DPAPI 加密保存在本机。下次点击同一设备时输入框虽为空，程序会自动用已保存凭据直连。注意：RDP 免密仅在**同一台主控机、同一个 Windows 用户**下有效（这是 DPAPI 的安全设计）；Credential Guard / 空密码账户会自动回退手输，若公司机器启用了 Credential Guard 仍弹密码框，请在 Windows 凭据管理器手动添加 `TERMSRV/<IP>` 条目——本项目不会绕过系统安全策略。

**连不上怎么办**：连接前会先做端口预检（自动轻量重试取最小延迟）；失败时页面会直接告诉你原因（如"被控端非专业版""服务未开启""防火墙拦截"）并自动展开针对该协议的分类排查清单，同时提供「端口预检」按钮可随时重测。

## 四·再补、网段识别与系统识别（v1.4.0 新增）

**扫不到设备？先看网段对不对**：设备发现页顶部有「扫描目标」选择器。程序会列出本机所有网卡网段并标注——**主网段**（真正连路由器的网卡，默认选中）、**虚拟网卡**（WSL / Docker / VPN / Hyper-V，已降权）。如果你有多个网段或程序选错，可切换网段，或点「手动输入网段」填 `192.168.10.0/24`（也可直接填单 IP）。扫描时 mDNS / ARP 发现的跨网段设备会被自动过滤，不会再混入 `172.18.0.1` 这类虚拟网关地址。

**系统类型怎么看**：设备卡上的系统标签带置信度徽章——**高**（协议横幅/握手确认，如 RDP X.224、macOS RFB 003.889）、**中**（MAC 厂商 / mDNS 机型线索）、**低**（端口/名称推测）、**未识别**。点开标签可查看具体识别依据，也可手动指定正确系统；手动指定后后续扫描不会再覆盖。这是有意为之：标准 VNC（RFB 003.008）在协议层无法区分 macOS 与 Linux，与其乱猜不如标注"未识别"让你确认。

**各系统协议口径**（依据 RFC 6143 / Apple / 微软 / 飞牛官方资料校准，详见 `docs/13-v1.4诊断与重构方案.md`）：

| 被控端 | 原生协议 | 剪贴板 | 文件传输 |
|---|---|---|---|
| Windows | RDP（3389） | 原生重定向 | 磁盘重定向 / SMB |
| macOS | 屏幕共享（RFB/VNC 5900） | 取决于 Viewer 是否实现 Apple 扩展 | 标准 VNC 不含，用 SMB / RustDesk |
| Linux / 飞牛OS | VNC（5900）或 xrdp（3389） | 取决于客户端 | 用 SMB / RustDesk |

RustDesk 为可选通道，其剪贴板与文件传输由官方客户端原生提供；LanDesk 只调起客户端，不读取共享内容。连接对话框会按「系统 × 协议」显示每项能力的来源与前置条件。

## 五、被控端开启指引

### Windows（RDP，3389）
1. 设置 → 系统 → 远程桌面 → 启用“启用远程桌面”。
2. 确认本机为 Windows 10/11 **专业版/企业版**（家庭版无传入 RDP 服务端）。
3. 防火墙放行“远程桌面”规则；记录被控机 IP。
4. 被控账号需有密码，且属于 Remote Desktop Users 组。

### macOS（VNC，5900）
1. 系统设置 → 通用 → 共享 → 打开“屏幕共享”。
2. 点击右侧 `i`，设置允许访问的账户与 VNC 密码（至少 8 位）。
3. 防火墙允许屏幕共享；记录 Mac 的 IP。

### Linux（VNC，5900+）
- X11 环境：安装 `x11vnc` 或 `tigervnc-server`，例如 `x11vnc -forever -passwd 你的密码 -rfbport 5900`。
- Wayland 环境：优先使用发行版自带的 VNC 方案（如 GNOME 的“远程桌面”/`gnome-remote-desktop`），或改用 TigerVNC 的 Xorg 会话。
- 防火墙放行 5900；记录 Linux 主机 IP。

### 飞牛OS（fnOS，5900 / RustDesk）
1. 飞牛OS 桌面 → 设置 → 远程访问/桌面 → 开启内置 VNC（默认 5900），设置访问密码。
2. 或在应用中心安装 RustDesk 官方客户端，记录其设备 ID 与临时密码。
3. 防火墙放行对应端口。

> 各被控端服务必须**预先由设备所有者开启**。若扫描显示端口未开放，请先在对应设备上完成上述配置，或在 LanDesk“设置 → 手动添加设备”中直接添加 IP。飞牛OS 没有稳定公开的专属 mDNS 类型，识别靠 HTTP `Server` 头 + 5666 端口。

## 五·补、共享剪贴板与文件传输（v1.1.0 新增）

所有共享能力都基于各系统/客户端**原生功能**，LanDesk 只负责调起与开关配置，不实现协议、不经手文件内容。

### 能力矩阵

| 连接通道 | 共享剪贴板 | 文件传输 | 由谁提供 |
|---|---|---|---|
| **RDP**（Windows↔Windows） | ✅ 会话内重定向 | ✅ 会话内磁盘重定向（拖拽复制） | Windows RDP 原生 |
| **SMB 文件通道**（全平台，点“传文件”） | — | ✅ 资源管理器打开 `\\IP\共享名`（**不承诺断点续传**） | Windows 资源管理器 + 对端 SMB |
| **RustDesk**（可选） | ✅ 会话内同步 | ✅ 客户端内“文件传输” | RustDesk 官方客户端 |
| **VNC**（macOS/Linux/飞牛OS） | ✅ 取决于 Viewer | ❌ 标准 VNC 无文件传输 | 外部 VNC Viewer |

### 使用方式

- **剪贴板**：连接对话框里“共享剪贴板”开关控制（RDP 默认开）。连接后即可在两台电脑间复制文本/图片。
- **RDP 会话内传文件**：开启“文件传输（磁盘重定向）”后，远程桌面里会看到本机磁盘，直接拖拽即可复制。注意：被控端可访问你映射的磁盘，**仅对可信设备开启**；用完可在连接对话框关掉。
- **跨系统传文件（推荐给 macOS/Linux/飞牛OS）**：在设备卡片点“传文件”，填入对端共享名，LanDesk 用资源管理器打开 `\\IP\共享名`，像本地文件夹一样读写。对端需先开启 SMB 文件共享：
  - Windows：启用网络发现与文件共享，设置共享文件夹；
  - 飞牛OS：控制面板开启 SMB/文件服务，用共享文件夹；
  - macOS：系统设置 → 通用 → 共享 → 文件共享（SMB）；
  - Linux：运行 Samba 并配置共享目录。
  - 常用共享名可在“设置 → 共享能力”里保存，之后自动填入。
- **连接优化**：连接前会先做 TCP 端口预检并显示往返延迟；端口未开时直接给出提示，避免盲目调起客户端。RDP 使用局域网带宽自动检测与连接类型优化。

> 隐私说明：LanDesk 不读取、不缓存、不上传剪贴板内容与传输的文件；这些能力完全由会话/系统承载。
> 限制：Explorer 的 SMB 复制**不支持可靠断点续传**，现有「传文件」通道不承诺断点续传，大文件中途失败需重新复制（`robocopy /Z` 断点续传属后续演进，见 `docs/11`）。

## 六、协议与开源许可边界

- **RDP**：调起 Windows 系统自带 `mstsc.exe`。
- **VNC**：调起你自己安装的 VNC Viewer（TigerVNC / x11vnc 为 GPL，RealVNC 等各有许可）。LanDesk **不随包分发、不内嵌、不修改**这些程序。
- **RustDesk（AGPL-3.0）**：仅通过命令行 `rustdesk.exe --connect <id>` 或 `rustdesk://` 链接调起**独立安装的官方客户端**。进程间调用不构成衍生作品；本项目**禁止内嵌、捆绑、修改或重新分发 RustDesk 代码**，否则会产生 AGPL 传染义务。
- 本项目自研代码采用 **MIT 许可证**。

## 八、已知限制

- 主控端仅支持 Windows（RDP 依赖系统 mstsc，文件传输依赖资源管理器/SMB）。
- RustDesk 为 P2 可选能力，依赖本机已安装官方客户端。
- 扫描以本机所在 /24 为主；多网卡 / AP 隔离环境请手动添加 IP。
- 打包后 WASM 若定位失败会降级 JSON 存储，功能不变但查询走 JSON 文件。
- **VNC 为明文协议**：基础 RFB 只有 None/VncAuth，VncAuth 仅保护最多 8 字符密码，帧缓冲/键鼠/剪贴板全明文；加密需 VeNCrypt/SSH 隧道且取决于 Viewer 与服务端协商，LanDesk 只调起、不控制协商，**绝不宣称「VNC 已加密」**，仅建议可信局域网并引导改道 RDP / RustDesk / SMB，且标准 VNC 不含文件传输（请用 SMB 通道或 RDP）。
- **SMB 传文件不承诺断点续传**：Explorer 的 SMB 复制不支持可靠断点续传；大文件中途失败需重新复制。SMB 传文件需对端预先开启文件共享并给出授权账号；剪贴板/磁盘重定向请仅在可信设备间开启。
- **WoL 为 best-effort**：UDP Magic Packet 无回执，需被控端 BIOS/网卡预先开启 WoL，跨网段通常无效。**Windows 原生 RDP 默认不通过 mDNS 广播**，RDP 识别以 3389 端口 + X.224 握手层指纹为主。
- 跨设备的“常驻剪贴板同步”（断开会话后仍同步）需要中心服务，与本项目“无服务端”定位冲突，不在范围内。
- RDP 免密仅在同一台主控机、同一个 Windows 用户会话下有效；Credential Guard / 空密码账户自动回退手输，本项目不绕过系统策略。

## 九、隐私与数据边界（v1.3.0）

LanDesk 的设备发现、连接与凭据存储全部在本机/局域网内完成，连接数据、凭据、被控画面及局域网设备信息永不离开本机。**当前版本（v1.3.0）零遥测**：不采集、不上传任何诊断或遥测数据，不自动上报崩溃；日志仅本机保存、保留 30 天。凭据经 Windows DPAPI 加密后仅在本机当前用户下可解密；生成 RDP 免密凭据时密码只经本机管道传递给系统组件，不进入进程命令行、不明文落盘、不写入日志。

**关于预留开关**：设置中保留一个默认关闭的预留开关（`src/shared/types.ts` 的 `telemetryConsent` 字段及设置页对应开关），**当前版本无论其取值都不产生任何采集或上报行为**，仅为未来版本预留，请勿误以为开启后会上传数据；该开关文案由设置页另行同步说明。当前版本**不含崩溃自动上报**。

**日志与脱敏口径（与 v1.3 结构化日志实现一致）**：运行日志为结构化 JSON Lines，**仅写入本机 `userData/logs/*.jsonl`**、仅保留最近 30 天、按大小分片轮转，兼容旧文本日志读取。脱敏按字段清单执行：**密码类字段、账号名、含用户名的本机路径、共享名会被脱敏**；**局域网私有 IP 保留完整**（按 IP 串联并定位一次连接是诊断必需）；**状态快照里的网段与本机路径做掩码 / 去用户名处理**。日志**仅本机保存、不自动上传**，字段清单见 `docs/12` 第三节。

**诊断导出是用户主动、纯本地行为**：主进程把自包含诊断包写到本机固定路径 `userData/diagnostics/`，并返回可复制文本；只有你手动复制该文本、或自行把导出的文件提供给 AI / 他人，数据才会离开这台电脑，**不存在任何自动外发通道**（见第十节）。状态快照与诊断包均不含任何凭据、明文密码或 DPAPI hex。共享剪贴板与文件传输由系统/客户端原生能力承载，LanDesk 不读取、不缓存、不上传其任何内容。诊断导出始终是用户主动、纯本地的行为；当前版本不提供任何上报通道，设置中的预留开关不产生任何实际效果。

## 十、运行状态与诊断（v1.3.0 新增）

LanDesk 无服务端、零遥测，**任何 AI / 云端都无法远程连进本软件**；状态以「本地结构化产出 + 用户主动导出」的方式提供。三种获取运行状态的方式，任选其一：

1. **设置页面板（推荐）**：设置 → 「运行状态与诊断」查看运行状态快照（版本 / 平台 / 架构 / Electron 版本 / 运行时长 / 存储模式 / 协议可用性 / 设备·凭据·会话计数 / 最近会话 / 最近错误），并可按 级别 / 模块 / 时间 / `traceId` / 关键字 查日志（默认 200 条、上限 1000）。
2. **导出诊断包**：点「导出诊断包」写入本机 `userData/diagnostics/` 固定路径，面板同时给出**可复制文本**；点「一键复制」即可把文本交给 AI 分析，或把导出的文件交给能读本地文件的 AI。
3. **直接读日志**：直接打开本机 `userData/logs/*.jsonl`（JSON Lines，敏感字段已脱敏，局域网 IP 保留）查阅或摘取片段。

诊断包按 `traceId` 串起一次完整连接（预检 → 凭据决策 → 适配器调起），便于定位「连不上 / 为什么慢 / 为什么没免密」。快照与诊断文本**不含任何凭据、明文密码、DPAPI hex**，网段与本机路径已做掩码 / 去用户名处理；日志含完整内网 IP，直接贴片段给 AI 前请自行确认可接受，是否分享由你决定。字段规范与操作步骤见 `docs/12-v1.3可观测性与诊断方案.md`。

## 十一、管理页入口（内网 Web 管理端口 · v1.3.0 新增）

设备列表中，对扫描发现开放了 Web 管理端口（如 8000 / 8001 / 548 / 5985，常见于 NAS、飞牛OS、Windows 管理接口等）的设备，提供「管理页」入口：用**系统默认浏览器**打开 `http://IP:端口`，方便直接进入设备自带的管理界面。

安全约束（防 SSRF，严格校验，**不开放任意 URL**）：

- **仅内网 IP**：目标必须是内网地址，拒绝公网地址、域名以及任何非预期协议；
- **端口白名单**：端口必须在该设备 `detectedPorts`（扫描发现并识别过的开放端口）白名单内，不接受任意端口输入；
- 入口只由发现结果生成 `http://IP:端口`，用户不能手工填入任意 URL；LanDesk 不发起任意 URL 请求、不代理网页内容。

打开的是设备自带的 Web 管理页面，账号与鉴权由该设备自行承载，LanDesk 不读取、不代填、不缓存其凭据。
